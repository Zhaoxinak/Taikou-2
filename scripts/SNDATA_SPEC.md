## 2. SNDATA 顶层字节布局（✅ 由 0x47f350 主解析器实证）

```
0x0000   16B   "TAIKOU2_SCENARIO" 文件头 magic
0x0010    2B   对象[0x90]   —— 剧本签名（sc1=4bb8, sc2=1380）
0x0012    2B   对象[0x94]   —— 校验/填充哨兵（byte0^byte1 = 密钥！sc1=0x0c, sc2=0x0a）
0x0014  700B   写入全局 0x519288  —— 700 武将各 1 字节「登场/激活」标志（值域 0/1，354/346 分割）
0x02d4  700B   写入第二缓冲（0x4eb5c0 分配）—— 旗标/状态码（值域 0/255/1）
0x0598  ~39424B  加密流（XOR 解密，详见 §3）—— 含全局状态段 + 49B 实体记录区
0x9F81   23B   尾区
```

- `0x519288` 的 700B **不是城池归属**，而是「武将是否登场」布尔数组（已交叉验证：武将#13 信长=1、#16 藤吉郎=1、#27 庆次=0）。
- **`0x598` 处的字节非 `0x39`**（sc1=0x0c, sc2=0x0a），故 0x47f350 不会额外读 49B 到 0x519640。

### 2.1 「833×49」的真相（重要纠偏）
文件 40856 = 16 + 833×49 + 23 的整除吻合**属实**，但那 833 条 49B 记录**不是从 0x10 明文排列**。
- `0x47d890`（49B 记录访问器）的 `offset = idx*49 + 0x10` 是**文件明文视图**的读取；
- `0x47f350`（主解析器）走的是**从 0x598 起的解密流**，两者访问同一文件的不同逻辑层。
- 解密流（0x598 起 39424B）实测包含：~608B 全局状态段 + 实体记录区（详见 §4）。

## 3. XOR 单字节加密流机制（🚨 本回合核心突破）

- `0x47f350` 把对象[0x94] 改写为 `byte0 ^ byte1`（sc1=0x0c, sc2=0x0a），此即**解密密钥**。
- `0x47d960`（解密缓冲初始化）：分配 **0x2000（8192）字节**滑动缓冲 → 从文件 0x598 读 0x2000 密文 → 对每字节 `xor 密钥` 解密 → 用尽后 `0x47d9b0` 再读下一块 0x2000。
- 读取原语：
  - `0x47da10` = 从解密流读 1 字节（缓冲满则重填+XOR）
  - `0x47da50` = 从解密流读 2 字节（小端 word）
  - `0x47da80` / `0x47dac0` = 写 1/2 字节（存档方向）
- 密钥同时是「默认填充哨兵」：sc1 用 0x0c 填充、sc2 用 0x0a 填充（解释此前所有「0c0c/0a0a 填充族」现象）。
- **解密后**：值域从窄分布展宽为 0–255 全分布（distinct=256），证实解密正确。

## 4. 49 字节记录格式与扇出（✅ 0x47fc60 / 0x47ff68 实证）

`0x47d890` 读取单条 49B 记录后，`0x47fc60`/`0x47ff68` 将其扇出：

| 记录偏移 | 目标 | 说明 |
|----------|------|------|
| `[0:2]`  | 0x509648 系（10B 区，push 0xa）| 经 `0x4ebe60` 反序列化 |
| `[2:4]`  | 另一 10B 区，经 `0x4ebe60` | |
| `[4:6]`  | 经 `0x49f120` 比较/分类 | |
| `[0x13=19:]` | 0x522c60 | |
| `[0x20=32:]` | 0x522c70 | |
| `[6:49]`（43B）| **0x522c88** | 主体 payload，经 `0x4ebfe0` 整体拷贝 |

- `0x522c88` = 43B 实体结构缓冲；`0x522ce4` = `0x522c88 + 0x5c(=92)` → **每城 1 字节的 92 城数组**（城数强吻合）。
- `0x47ff68` 是**单条记录处理器**（非遍历循环）；它先判 record[0:2]/[2:4]/[4:6] 是否全 0（空记录则跳过），否则按类型字符串（`0x50d834` 等）匹配后触发场景初始化。

### 4.1 「49B 记录不是城池归属直接赋值表」（🚨 已双重确认）
- 对 43B payload 全偏移 + 全 word 偏移扫描：**无任何偏移值域被收紧到 0–91（城码）或 ≤699（武将id）**，所有字节值域 2–254。
- 推论：城码/武将id **不以裸小整数**存于 49B 记录；它实为「模板 + 稀疏覆盖」的剧本参数/旗标/事件块。
- 因此「谁拥哪城、谁效忠谁」的真实赋值表在 **SAVEDATA 的运行时状态区**（328KB，不加密）或 SNDATA 的解密流实体区。

## 6. 引擎加载架构（✅ 已定位，修正 40960→20480）

| 函数 VA | 作用 |
|---------|------|
| `0x47d720` | `LoadSNDATA(idx)`：idx=0/1 选 SNDATA1/2，调 `0x4802e0` 加载 |
| `0x47d780` | `LoadSAVEDATA`：用 `"A:SAVEDATA.TR2"`，读 **0x50188≈328K** 字节（完整场景状态）|
| `0x47d860` | 大块访问器：`offset = idx*20480 + 0x198`（**非 40960**，= `idx*5<<12`）；`fseek` 到文件对象[0] |
| `0x47d890` | 49B 记录访问器：`offset = idx*49 + 0x10`，读 49 字节 |
| `0x47d8d0` | 第二 49B 记录访问器（`0x4411d0` 变体）|
| `0x47f350` | **SNDATA 主解析器**：读头+700+700 → 建解密缓冲(0x47d960) → 调 17 段序列化器 |
| `0x47fb80`/`0x47fc10` | 场景加载：LoadSNDATA → 0x47d860(seek) → 0x47f350/0x47f5c0(解码) → 0x47d850(清理) |
| `0x47fc60`/`0x47ff68` | 单条 49B 记录处理器（扇出到 0x522c88/0x522c60/0x522c70）|
| `0x47fd10` | 第二 49B 记录处理器（调 0x47d8d0）|
| `0x4e8625` | **主循环①**：遍历记录，按类型串匹配触发场景初始化；判 0x5205fe（场景模式）分支 |
| `0x4e89cd` | **主循环②**：调 0x47fd10 + 0x47fc10 处理记录，按 0x5205fe 分支 |

> 注：`0x47d860` 的 `idx*20480` 步进说明它被更大文件（如 SAVEDATA）复用；用于 SNDATA 时 idx 实际仅 0/1（offset=0x198 或 0x5198，后者仍在 40856 文件内）。

## 11. SAVEDATA 容器 + 归属派生（2026-08-25 续破）

### 11.1 SAVEDATA 容器
- `SAVEDATA.TR2` = 328088B = **408B 头 + 16 × 20480B 区块**（`0x198` 起每块 20480）→ **16 存档槽**，每块 = 完整场景运行时态；**不加密**（XOR 密钥=0）。
- 块0 @`0x198` = `"TAIKOU2_SCENARIO"`；@`0x1ac` = **700B 武将登场标志**(`0x519288`)；@`0x48c` = 92 word 区（实测全 0 = 旗标数组，**非归属表**）。

### 11.2 XOR 解密流（主解析器 `0x47f350`）
- 密钥 `obj[0x94] = header[0x12] ^ header[0x13]`（SNDATA 剧本1=0x0c / 2=0x0a；SAVEDATA=0）。
- `0x47d960`：分配 0x2000 滑动缓冲，逐字节 XOR 密钥，用尽再填；`obj[0x92]` = 累计校验和。

### 11.3 序列化器架构（32 函数 = 16 实体类型 × 读/写，`0x47dae0…0x47f1b0`）
- 主解析器依次调用读序列化器，从 XOR 流还原全局态与各实体数组。
- 已确认实体数组长度：**370 / 200 / 49 / 30 / 25 / 20 / 13 / 8 / 6 / 5** = 系统/查表型（技能·官职·町·据点），**不含 92 城 / 700 武将动态归属**。
- 49B 记录处理器 `0x47fc60` 写场景态 `0x522c88 / 0x522c60 / 0x522c70 / 0x522ca0`。

### 11.4 归属派生规则（谁拥哪城 / 谁效忠谁）
文件中无平铺赋值数组，归属由 BSDATA 每武将字段派生：
- `home_city@49` = 地名表索引（0–48 国 / 49+ 城·町；**255 = 未登场**）。
- `status@57`：`7=大名`(城主) / `4=家老` / `3=足轻头` / `1=足轻组头` / `0=无`。
- 验证：织田信长#13 与柴田胜家#1·森可成#2·木下藤吉郎#16 同 `home_city=66`（清洲/尾张一带）；前田庆次#27=`255`（未登场）—— 与史实一致。
- 推导：每城（按 `home_city` 归组）城主 = 该组 `status==7` 者（否则最高 status）；某武将「主君」= 其 `home_city` 组城主。
- EXE 地名表 `@0x506ca8` = 370 条（国名 0–48 / 城·町名 49–291 / 职种名 292–369），GBK 变长 null 结尾（省块 stride≈9 干净；精确 stride 待定）。
