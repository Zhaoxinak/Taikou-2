## 2. 原版文件 → 格式 → 加载方式

原版目录：`Taikou2 Original/`（149 文件，**仓库不打包**，本机才有）

| 文件 | 格式 | 怎么读 |
|---|---|---|
| `BSDATA1.TR2` / `BSDATA2.TR2` | **700 × 59 B 明文**（无加密无 magic） | 直接按 59B 切分即可 |
| `SNDATA1/2.TR2` | `TAIKOU2_SCENARIO`；头 16B，**XOR 加密流** | key = `byte[0x12] ^ byte[0x13]`（sc1=`0x0c`，sc2=`0x0a`）；解密区 `[0x58C..EOF)`；`file[0x10..0x11]` = 校验和 |
| `SAVEDATA.TR2` | `TAIKOU2_SAVEFILE`；**8 槽 × 40960 B** | 槽元数据 49B：年/月/日 + 主角名13 + 国13 + 地+身分17 |
| `GAIJI.TR2` | 16 × 34 B = 544 B | `u16` 源码 + 32B 的 16×16 1bpp 位图；GBK `0xA140..0xA14F` 被劫持为外字区 |
| `*.KOS` | **1 字节 XOR 密钥 + 标准 WAV** | `raw[0]`=key（全为 `0xAE`），`raw[1..]` 逐字节 XOR → RIFF/WAVE |
| `*.LZW` | 光荣 LS11 变体 | 文本类（`MESSAGE1-4`/`HEXMES`）→ MSGX 文本；像素类 → **豁免** |
| `HJMAPDAT.LZW` | 38 张 × 1700 B | A 头 20×9/180B + B 地形 40×19 + C 部署 40×19 |

**TR2 是容器扩展名** → 必须按加载点分派解析器，不能只看扩展名。

> 🔧 **解码器在哪**：**LS11 解压（LZW）现成实现 = `scripts/real_assets.py` 的 `ls11_decompress(data)`**（第 38 行）。
> 它被 4 个 ref 脚本间接覆盖（`anmseq_format_ref` / `idx_format_ref` / `event_text_xor_ref` / `gaiji_identities_ref`），
> 即**解压正确性有自测兜底** —— 直接用它，不要重写。
> ⚠️ 不要在 `_scratch/_graph_probe.py`、`_scratch/_analyze_maps.py` 里找（那是草稿副本）。

## 4. 字段速查

### 4.1 武将（BSDATA 59B / 运行期实体 47B）

**BSDATA 59B（模板）**

| 偏移 | 含义 |
|---|---|
| `+0x1b..+0x1d` | **技能 10 × 2 bit**（见下） |
| `+0x27` | 生年 − 1490 |
| `+0x30` / `+0x31` | 国 / 城（城索引 0..199） |
| `+0x32` | 功勲 |
| `+0x35` | 忠诚 |
| `+0x36` | 主君 word |
| `+0x38..+0x39` | 状态字（`職位 = byte[0x39] & 7`） |
| `+0x3a >> 4` | 主角槽 + 武将档 |

**技能位打包**（10 技能 × 2 bit，0..3 级）：
```
level_k = (byte[+0x1b + k//4] >> ((k & 3) * 2)) & 3     # k = 0..9
顺序 = 口才, 马术, 算术, 剑术, 忍术, 兵法, 洋枪, 筑城, 礼法, 茶道
```
> 🔴 名表实测是 **算术 / 兵法**（不是"算用/军学"，那两个串在镜像里 0 命中）。

**运行期实体 47B**

| 偏移 | 含义 |
|---|---|
| `+0x08` | 相性（word 的 bit 11–14） |
| `+0x0a..+0x0e` | 五维 |
| `+0x0f..+0x11` | 技能 10 × 2 bit（同上公式，基址改 `+0x0f`） |
| `+0x20` / `+0x21` | 最大体力 / 现在体力 |
| `+0x24` | 国索引 |
| `+0x25` | 在城 |
| `+0x2a` (word) | 主君（`0xffff` = 浪人） |

### 4.2 城（31 B × 200）

字段布局见 `../specs/GAME_DATA_SPEC.md §3.17.2`。S7 每城记录（16B）为其派生工作副本：

| S7 偏移 | 大小 | 源城表 | 钳制 | 语义 |
|---|---|---|---|---|
| `+0x00` | B | `0x0c` | 100 | 農商等级 |
| `+0x01` | B | `0x0f` | 100 | 生産率 |
| `+0x02` | W | `0x16` | 2000 | 地域 |
| `+0x04` | W | `0x18` | 2000 | 兵数 |
| `+0x06` | W | `0x12` | 30000 | 米 |
| `+0x08` | W | `0x14` | 30000 | 資金 |
| `+0x0a` | W | `0x10` | 50000 | 軍糧 |
| `+0x0c` | B | `0x0d` | 250 | 守城度 |
| `+0x0d` | B | `0x1a` | 200 | 次級民情 |
| `+0x0e` | B | `0x0e` | 200 | 民心/治安 |
| `+0x0f` | B | — | — | 类别(bit4-6) / 标志(bit0-3)，默认 7 / `0xc` |

## 6. 图像（豁免）——复刻怎么办

**不破解像素格式。** 复刻时：

- 用 `scripts/_decoded_grp/*.png`（已有 32 个解码产物）或**直接用原版裸图**。
- 资源名规则：EXE 里的盘符（`A:`/`B:`/`C:`）是**内部逻辑代号，不是真实路径**
  → Godot 里按**去前缀的裸名**在原版目录查文件。
- 中文版 BGM 走 `MP3/` 目录（不是 KOS）。

## 7. 避坑清单（前人踩过的坑）

1. **别信 `scripts/_probe/msgx/all_messages.txt`** —— 在 gitignore 可再生目录、常不存在、只覆盖 3091 条。
   权威是 `scripts/msgx_all_texts.json`（6211 条）。
2. **BSDATA 的"城"索引是 0..199**（200 条城表），不是 92。92 是城镇三件套的对齐数。
3. **技能名是 算术/兵法**，不是 算用/军学。
4. **阵形名不存在**，别去找。
5. **9 类兵种索引 ≠ 4 个兵种名**（`a∈[0,8]` vs 4 个名），别硬套。
6. **side0 恒吃 80% 伤害**是写死的不对称，复刻必须保留，否则平衡崩。
7. 跑自测时**会再生** `bsdata_format.json` / `bsdata_tail_fields.json`，记得 `git checkout --` 还原。

**来自归档 `docs/archive/REPLICATION.md` §6（时间无关的死路，仍有效）：**

8. **搜武将全名（如「织田信长」）会搜不到** —— 姓和名之间夹了 `00 00 00` 三个零字节，字节不连续。
   要搜就分开搜「织田」「信长」，或按记录逐条用 GBK 解码。
9. **`TaikouParser.parse_bsdata()` 是错误占位桩**（假设 100 字节/条，实际 **59 字节**，且没解任何字段）。
   **不要再改它去跑** —— 直接用 `bsdata.json`，或重写 Python 离线提取器（推荐，可重跑可校验）。
10. **KOS 音效无台词** —— 台词来自 `MESSAGE*.LZW`（GBK）。旧 `kos_message_map.json` 系误读 PCM，已废。
11. **`rmKOEI.bin` 是卸载程序 DLL，不是字体渲染器**（含明文 GBK 卸载字符串 + 文件删除 API，**无任何 GDI/字体 API**）。
    对话文本与武将名都是**明文 GBK 直解**。
12. **SNDATA 记录中的字段用 EXE 内部码**（GBK → 字形索引 → 字体位图），不是简单查表；
    需字体加载器 `0x424120`（见 `docs/archive/ENGINE_SPEC.md` §7）。

## 8. 建议的复刻顺序

1. **数据层**：BSDATA 700 武将 → 城表 200 → 国表 49 → 名称表（建 `Dictionary` 索引）
2. **文本层**：`msgx_all_texts.json` 导入，接 GBK 解码 + GAIJI 外字
3. **实体层**：按 §4 建 47B 实体结构（Godot 里用 `Resource` 或 `Dictionary`）
4. **玩法层**：先合战（`../specs/BATTLE_SPEC.md §9` 可直接实现），再内政/店铺
5. **表现层**：最后接图像（裸图）、音效（`_decoded_kos/*.wav`）
