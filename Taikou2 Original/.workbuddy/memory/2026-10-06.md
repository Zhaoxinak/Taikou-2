## ★ 顺手修掉 M3c 分页的一个真 bug（会影响面板与选孩正确性）
`cm_same` 开头 `mov eax,[esp+0x30]`（累计匹配数 L_MATCH）把 eax 冲掉，紧跟的 `mov [esp+0x14],eax`
把「第几个匹配」当成槽写进 L_SLOT ⇒ ① 姓名表按它取会取到**别人的名字**；② SLOT_ARR 存它 ⇒
选中后 `ent = 槽*47+pool` 算到另一个孩子；③ 面板读 KID_TAB/sched 也全错。
修法：写 `[esp+0x14]` 前补 `mov eax,[esp+0x08]; dec eax`（游标在 cm_scan 已 inc）。
⇒ 印证 M3c 分页确实还没做过实机（与 memory「待用户 fam13 冒烟」一致）。

## ★★ 实机首个 bug（用户截图：自宅 1560/5/21 卡住）—— 根因已修
**取证方法（无调试器、进程活着时拔现场，可复用）**：
- `Wow64GetThreadContext` 采全线程 EIP → 主线程 39/40 阻塞在 `win32u`(GetMessage)，**未进任何桩区间**
  ⇒ 非死循环/非桩内死锁；`IsHungAppWindow=False`。
- `ReadProcessMemory` 读埋点：`MENU_COUNT=11`、`CMD_PUSH=0`、`KID_NOTSAME_CITY=0`、`GROWTH_PASS=0`
  ⇒ 培养流程一次没走完，连一级「选孩子」都没过。
- 埋点 VA（本档）：GC 0x54D600（MENU_COUNT = +0x40）、KID_TAB 0x54D700、CMD_RING 0x550700、
  MENU_PTR 0x550920；MOD 基址恒为 **0x54B600**（M(x)=0x54B600+x；别再把 5551616 误读成 0x54C600）。

**根因**：原生对话框引擎 `0x47BED0` 的实参顺序是 **arg1=条目数**（入口 `mov edx,[esp+4]` →
`test dx,dx` → 拷贝循环以 `cmp ax,dx` 为上界）、arg2=串指针数组、arg3=样式。
`cm_hook` 把 `s_cnt(条目数)` 与 `s_flag(样式 2/4)` 传反（末推成了 s_flag）⇒ 引擎以为只有 2 项，
只画「休息/金库」、**不显示「培养孩子」**，且样式参数变成 cnt+1=3 ⇒ 点击无反应 = 卡死。
`cm_foster` 的四个子菜单一直是正确顺序，故只有这一处错、且躲过自检（自检没锁实参顺序）。

**修复**：`cm_hook` 改 `push [s_flag] / push edx / push ecx`；新增 `selfcheck_hook` 断言 +
`verify_children.py` **C23b2** 钉死顺序。重建后 **226/0**，big.exe 仍 1387520B。
**教训**：静态自检验不了原生函数的实参语义 —— 复用原生引擎前必须先反出引擎入口自己的取参方式。

## ★ 新增 `tkmon.py` —— 常驻崩溃监控器（附着式，用户报「大地图崩溃」后开）
**为什么新写**：既有三件都不顶用 ——
- `tkwatch.py` 只轮询埋点，**看不到崩溃现场**（上一轮跑完就只留下「读不到进程内存→游戏已退出」）；
- `dbg_crash.py` 自己 `CreateProcess` 起游戏，**抢用户操作权**，且它的 CONTEXT 用了带 Dr4/Dr5 的**原生 x86 布局**，
  64 位调试器读 WOW64 目标会**整体错位**（trace.py 里已注明 WOW64_CONTEXT 只有 Dr0-Dr3+Dr6-Dr7）；
- `trace.py` 只追 API，**0 次调用就结束了**（本轮 23:08 那次：退出码 1073741855 = **0xC0000005**）。

`tkmon.py` 要点（可复用）：
1. **你自己开游戏，它附着**：`CreateToolhelp32Snapshot` 找 `TAIK2W95*` → `OpenProcess` → `DebugActiveProcess`；
   `DebugSetProcessKillOnExit(False)`（否则监控一退就把游戏带走）。
2. **双 CONTEXT 布局自纠**：同一块缓冲用 WOW64/x86 两种结构各解一遍，取 EIP 落在已知模块（主模块优先）的那套，
   打印 `[CONTEXT=WOW64|x86]`，杜绝寄存器错位。
3. 平时每 0.7s 打心跳（日期 + 阶段标记 F/E/D/G/H + 21 个非零计数器），崩了立刻抓：
   异常码/读写目标、**EIP capstone 反汇编**、栈顶 48B、EBP 链 14 层，
   地址归属一次说清 `模块+off / MAIN RVA / MOD+off≈桩名 / 实体池 槽n`。
4. 进程退出后**回到等待态**，下次再开继续抓；`--once` / `--quiet` 可选。
5. 句柄返回类型必须显式声明 `restype=HANDLE`，否则 64 位句柄被 c_int 截断。

自检：语法 OK；`SysWOW64\ping.exe` 附着冒烟拿到完整事件序列 `3,6,6,2,...,1,...,5`（含 EXIT_PROCESS）⇒ 链路可用。
埋点表从 `_big_layout.json` 读，阶段标记 F/E/G/D/H = 0x54B676/75/77/74/78（与 dbg_crash.py 一致），MOD 基址 0x54B600。
产物：`.rev/tkmon.py` + `.rev/tkmon.bat` + `.rev/tkmon.log`（追加）。已在后台常驻等待。
