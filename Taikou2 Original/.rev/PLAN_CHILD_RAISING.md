> 立项: 2026-10-06 用户口述需求:「到龄自动元服 + 儿童成长曲线，父母也可以参与儿童的成长;
> 如果是主角的话，回到家会有单独的培养孩子的功能，比如培养、看书籍、锻炼等等，贴近游戏设计。」
> 本文 = 设计 + 落点 + 里程碑。**数值口径全部落在引擎已实证的原语上，不自造属性体系。**
> 前置: M2 预载器已建成并通过静态验收 (见 `.rev/CHILD_STATE_RECIPE.md` / `PLAN_CHILD_PRELOAD.md`)。

## 0. 玩家视角的闭环 (先定体验，再定代码)

1. 开局 (1560/1561) 世界里有这些孩子: 织田信忠 3 岁、武田胜赖 14 岁……他们**住在父亲所在的城里**，
   在族谱面板上看得见、点得开，但不进任何 AI 名单 (M2 配方已保证)。
2. 主角每月有一件事可做 (原生"每月一次主要指令")。培养**不抢**这个行动点，只花 **金 + 体力 + 时间**，
   口径照抄原生修行: 每日 2 金、天数自定、上限 `min(31-当前日, 金钱/2)`。
3. 培养有**四个教席**，效果差别看得见:
   - **主角亲自教导** (须与孩子在同一城; 主角相关五维 + 声望决定成功率)
   - **父母指导** (父/母与孩子同城，每月自动结算一次; 「虎父无犬子」按父的最高维加权)
   - **送设施修行** (道场/寺院/商家/茶人……按设施记录的"技艺等级 1..3 + 店主好感 0..100"计成效)
   - **自学/家风** (无人管的保底曲线，慢但不会为零)
4. 每月初结算，属性 +1 时**用引擎原生的升级提示器** (`0x4704e0`) 报「○○ 剑术 上升了」——
   不是 MOD 自造弹窗，看起来就是游戏自己的事件。
5. 满 15 岁 → **元服** (原生初始化例程 `0x4A4FC0`) → 摘除排除位 → 下个月起进原生家臣/评定/名单，
   被 AI 真实消费: 他的内政值进主命增量公式、武力+剑术进单挑判定、五维和进官职评定。
   **培养投入的回报由游戏自己演出，不是 MOD 面板上的数字。**
6. 元服时若玩家此前一直养他 → 可选择 仕官随父 / 主角直辖 / 自立浪人 (决策项 D2)。

## 1. 本轮新证据 (全部实测，脚本可重跑)

### 1.1 键空间钉死了 (此前两边的说法各对一半，现在统一)

| 字段 | 含义 | 命中率 |
|---|---|---|
| `word[ent+0x00]` | **池槽号** (= 姓/名表的索引) | 352/352 |
| `word[ent+0x02]` | **BSDATA oid** (身份真键) | 352/352 |
| `word[ent+0x1d]` | **父的 BSDATA oid** | 156 条父链中与姓名反查完全一致 (父子双方在场的 39 条 39/39) |

⇒ 族谱 MOD 过去"比 `ent+0`"实际比的是槽号，只是它同时拿槽号去索引姓名表(表也按槽)，才一直是对的；
而它通用分支里的 `[c+0x1d]==self` 是 **oid 比槽号 = 跨空间比较**，历史上没生效过 (柴田家走的是内置姓名匹配分支)。
**培养系统的亲子反查一律用 `oid`：`find_slot(oid) = 满足 word[ent+0x02]==oid 的 ent+0x00`。**

### 1.2 实体字段偏移复核 (352 槽逐字段)

五维 `+0x0a..0x0e` = 统率/武力/内政/外交/魅力 (346~350/352)
技能 10×2bit `+0x0f..0x11` (351/352 全对) · 生年-1490 `+0x1b` 低 7 位 (352/352) · 父 oid `+0x1d` (352/352)
体力上限/现役 `+0x20/+0x21` (351/352) · 俸禄 `+0x28` · 忠诚 `+0x29` (352/352) · 主君 `+0x2a` (349/352)
**国 `+0x24` / 城 `+0x25` (352/352)** ← 同城判定用这两个字节 · 状态字 `+0x2c` (335/352，其余是被引擎 init 改过)
(纠正: 父仓库 spec §3.5.6 写「技能=实体 +0x1b..0x1d」是把 BSDATA 十进制 27..29 与实体偏移混写了，实体侧以本表为准。)

## 2. 数值模型 (可直接实现，也可一眼看出是否公平)

### 2.1 生命周期分档

| 年龄段 | 阶段 | 可做 | 成长权重 | 备注 |
|---|---|---|---|---|
| 0–6 | 幼 | 家风(自动) | ×0.4 | 只吃父母同城的被动加成 |
| 7–11 | 童 | 读书/习礼/见习 | ×1.0 | 开始可被玩家下指令 |
| 12–14 | 少年 | 全活动 + 修行(可跨月) | ×1.5 | 修行的黄金期，收益最高 |
| 15 | 元服 | — | 冻结 | 摘除排除位，交原生 AI |

> **"年龄段"一律按引擎口径 = 虚岁** (`0x49A5C0`: 当前年 − 生年 + 1)，不是周岁。
> 落地后的月增是权重 ×0.35 的**百分定点** ⇒ `14 / 35 / 52` 点每月，累加满 100 才给 1 点 (向下取整，余数跨月进位)。
> 虚岁每逢**新年** +1 (不是距开局 12 个月)，所以期望表还要带开局月 —— 见 §6.4 的 `start_month`。

### 2.2 起始曲线与目标

- 起始(实例化时)五维 = `(史实成年值 + 1) // 2` (round-half-up 的折半)；**下限 5**。
  M3b-2 已落: 只在 `make_child` 这条路写 (`init_stats`)，每月复臂不重置 ⇒ 埋点 `CHILD_INIT5` 一次性的。
- 每条维度有一个**天花板** = 史实成年值 (BSDATA 记录里带来的原值) ——见决策 D3。
- 自然保底 (完全不管): 每月按 `阶段权重 × 0.35` 点向天花板收敛 (取整后每月 0 或 1 点)。
  ⇒ 放着不管也能长成"平庸版史实人物"，但到不了天花板。
- 培养产出 = **点** 而非百分比: 每点训练消耗教席与金钱，直接 `+1` 走原生饱和加，杜绝"读档刷满"式收益。

### 2.3 一次活动的成效公式 (月结算时逐条消费) —— **M3b-3 已按此实现，见 §6.6**

企划原式(小数)与落地版(整数百分点)同形，桩里一律用**百分整数**，避免 16 位定点误差:

```
P = clamp( P0 + T + B + R − D , 5 , 85 )        判定: rand(100) < P  ⇒  +1
  P0 = 10            活动基础成功率(百分点)
  T  = 教席表 TEACH_TAB[teacher]      自学2 / 主角20 / 父15 / 母10 / 师匠12
  B  = min( ACT_TAB[act].b + 5×档次, 15 )   档次 = CMD_RING 条目 +3 的低 2 bit
  R  = 亲密/10       桩用 (bond*103)>>10 实现 (0..100 内逐值 = floor(bond/10)，亲密先夹 100)
  D  = 当前值/4      shr 2 (越高越难再涨，与原生 sat_add 的 16-值 同形)
  掷骰: call 0x4EBD60(100)  [引擎 LCG, 种子 0x50DE48 ⇒ 可反推/可复现]
  命中 ⇒ 该维 +1 走原生写手 0x4A2F80+d*0x20 (内部 sat_add 上限 0x64 ⇒ 硬顶 100 = D3"可突破史实值")
```

与企划的三处**有意偏差** (都记在 §6.6): ①没有"阶段权重 0.4/1.0/1.5"(少年期加速已由 §2.1 的自然保底档位承担，
两乘会顶到 85% 夹顶失去区分度); ②`T` 已由 M3d 改为能力驱动 (主角=`min(30, 主维*25/100 + 身分)`、父=`min(28, 最高维*22/100)`)；其余教席(自学/母/师匠)仍走常数表; ③`R` 用 /10 而非 ×0.10 的浮点式。

## 3. 元服 (M4) 与其后闭环

1. 月钩成长桩里 `age = call 0x49A5C0(ent)`，`age >= 15` ⇒ 执行 `CHILD_STATE_RECIPE.md` §S4 五步:
   `nib_set(0xf)` → `bit4 清(0x49A6D0(0))` → 归属（**先随父 `0x4A5100(本人,父)`，失败退本国国主 `0x4A5290(本人)`，再退浪人**）
   → 埋点。**~~push ent; call 0x4A4FC0~~ 已按字节证伪**：派发器的门是 `test byte[+0x2d],7`（身分码），身分码=0 的人只走
   不挂载的短路径 ⇒ 喊它等于什么都没做。**也~清儿童位图位~**：位图留着，孩子元服后仍归 MOD 认领（面板/影子档按位图整段存取）。
2. 元服瞬间**不拉属性、不改培养成果** (元服值 = 之后 AI 眼中的他)，靠预载桩 `nibble==0xf ⇒ 不碰` + 成长桩 `cmp al,0xb` 两道门保证**只元服一次**。
3. 归属 (D2) 实际落地的三条 = KID_TAB+10 的**读数**（1 随父 / 2 国主 / 3 浪人）:

2. 写链 `0x47DF00` 的唯一调用点 `0x47F6AF` 在 `0x47F5C0` 内；读链 `0x47DCE0` 的唯一调用点 `0x47F45B` 在 `0x47F350` 内 ⇒ **`0x47F5C0`=保存驱动 / `0x47F350`=载入驱动**。
3. `callers(0x47F5C0)` 只有一个 `0x47FC40`，位于保存派发器 `0x47FC10`；`callers(0x47F350)` = `0x47FB4C/0x47FBBE/0x47FBE3`(载入派发器 `0x47FB80` 的两遍 + 剧本切换)。
4. `callers(0x47F2A0)` 只有 `0x47F71F` ⇒ child_stub 的"载入钩"其实**在保存驱动里**，历史命名保留，行为不改(幂等)。
5. 两个派发器的"链跑完、原生句柄还没关"那一发 `call 0x47D850` 位置完全对称：保存 `0x47FC49`(`E8 02 DC FF FF`)、载入 `0x47FBEE`(**`E8 5D DC FF FF`**)；载入派发器两遍(预校验 gate=1 / 真读 gate=0)**收敛到同一发 close** ⇒ 每方向恰触发一次。

**做了什么** — 一处 881B 桩 + 一块 320B 数据区 + 两发 5B 补丁 (`build_big.py` 的 `4j4) M6`)：

| 件 | 位置 | 说明 |
|---|---|---|
| `sc_save` trampoline | `0x551700` (站点 `0x47FC49`) | `pushad / mov esi,ecx / call sc_save / popad / call 0x47D850 / jmp 0x47FC4E` —— 原生 close **照原样重放**，只是排在它前面干活 |
| `sc_load` trampoline | `0x551713` (站点 `0x47FBEE`) | 同形，回 `0x47FBF3` |
| 影子档 | `TKMODSAVE_0.DAT`..`_7.DAT` | **52902B** = 头 `0x30` + 扩展槽实体 30738 + 姓行 4578 + 名行 4578 + 位图 128 + `KID_TAB` 12288 + `CMD_RING` 544；CWD 相对路径(引擎自己也砍掉 `X:` 走相对，见 `0x4EC8C0 add eax,2`) |
| 系统调用 | 只用 Win16 兼容导出 | `OpenFile@0x4FB07C` / `_lwrite@0x4FB090` / `_lread@0x4FB0A0` / `_lclose@0x4FB09C`，各**恰 1 处包装**(C24/selfcheck 都核)；保存 `0x1002`(RW\|CREATE，CREATE 会截断 ⇒ 一槽一份文件)，载入 `0` |
| 数据区 `SC_DATA` | `0x551D00` | 路径模板/头缓冲/**六段描述符表(两方向同一张)**/句柄/槽号/摘要/游标/47B 空槽模板/OFSTRUCT |

**完整性口径 —— 只信"读/写满请求字节数"**：头 1 处 + 六段循环各 1 处 = **4 处 `cmp eax,ecx`** 闸门，
任何一段没满就 `REJECT` 归零。⚠️ 曾设计过 `_llseek(h,0,2)` 探长度 —— **踩坑**：seek 到档尾会把**读位置**一起带走，
后面 `_lread` 一个字节也读不到 ⇒ 每次载入都 REJECT+reset。截断本来就被"每段读满额"抓住了，`_llseek` 直接删掉。

**摘要 = 配对键，不是防伪**：基址 `0x53C000`、条数 `0x172`，每条 `+0 双字 → 跳 +4..+7 → +8..+43 九个双字 → +44 字 → +6 尾巴`，
每取一次 `add ebx,v; rol ebx,3`(文本 4 处、运行时每条 12 步)，步长 `8+…+3 = 47`。
**必须跳过 `+4..+7`** —— 那是派生指针，运行时按 `idx*47+poolbase` 重算(`0x47DD64`)，写进摘要会造成假 REJECT。
保存/载入 `call` **同一段实现**(C24p) ⇒ 影子档自校验与内存实际内容绑死，两方向不可能各算一套。

**失败语义 (一律归零，不猜)**：`MISS`(没文件) / `REJECT`(头字段、段长或摘要不符) → `sc_reset`
(47B 模板 + id word 复原扩展槽、7B 行 `rep stosb` 清姓/名、位图/`KID_TAB`/`CMD_RING` 整块清)；
`GATE`(`[obj+0x8c]!=0`，原生预校验失败) → **一个字节都不碰**。

**验收 (全静态，未启游戏)**: `verify_children.py` **136 → 156 项全过**；`child_save.py` 自测绿；
`build_big.py`/`verify_appear.py`/`verify_fam.py` 无回归。C24 一族里最有价值的三档：
- **C24j/k/l 头字段"写了就比"** —— 从 exe 字节把 `mov [hdr+k], imm` 与 `cmp [hdr+k], imm` 两边**逐字段配对**，
  立即数不同值就 FAIL；同时断言头缓冲 `0x30` **之外**没有任何定值写/比(防把常量误写进 scratch)。
- **C24m 方向不可能漂移** —— 两处 `mov eax, 描述符表` 是环入口，各自段内的直接 call 目标必须只有一个，
  再顺着那枚包装读到它的 IAT：写环 ⇒ `_lwrite`，读环 ⇒ `_lread`。段序/长度两方向共用一张表。
- **C24o2 参数真被用上** —— 不只看文本里有 `mov edx,0x1002`，而是要求它**下一拍就是 `call sc_open`**；
  桩里有两枚 `xor edx,edx`(另一枚是 `sc_slotpath` 的槽号累加器)，只有紧跟 open 的那枚算载入标志。

**实机手测配方** (`tkwatch.py` 会打 `[成长]…影子档: 保存a 落地b 写错c | 载入d 复原e 拒收f 无档g 门h 槽错i`):
1. 开局养几个月(下几条培养指令) → **保存** → 游戏目录应出现 `TKMODSAVE_<槽>.DAT`，**大小 52902 B**；`SIDECAR_SAVED` +1 且 `SIDECAR_WERR` 仍 0。
2. 完全退出 → 重新载入该档 → `SIDECAR_LOAD`+1、`SIDECAR_RESTORE`+1；孩子还在、五维/亲密度/`KID_TAB` 与存前一致。
3. 身份式当场核：`SAVE = SAVED + WERR`、`LOAD = RESTORE + REJECT`；`SIDECAR_SLOT` **应恒 0**。
4. 负路测试(想验证不会写坏)：删掉影子档再读 → 应 `MISS`+1 且孩子由下一月月钩重建；把影子档截断几字节再读 → 应 `REJECT`+1(不是崩)。

**已知边界 (留给后续，不当 bug 藏)**

  `0x172` 这个界是 M5(生孩子/联姻)要动的唯一杠杆，届时按同一套摘要/闸门口径扩。

### 6.10 M3c 分页落地记录: 一级「选孩子」翻页 (2026-10-06，纯静态、不启游戏)

**先把「12」这件事钉死** (`.rev/probe_listdlg.py`，只读 big.exe；两条独立证据)
- **控制流**：`0x47BED0(count, dword* 串指针数组, flag, 0, 0)` = cdecl、5 次 push、`add esp,0x14`；进门 `mov edx,[esp+4]` /
  `sub esp,0xa0`，拷指针最多 `cmp ax,0x28`(40) 个，然后 `call 0x47BE00`。内层 `0x47BE00` 一进门就是
  `mov edi,[esp+0x20]` → `test di,di / jle 0x47be8a` → `cmp di,0xc / jg 0x47be8a`，而
  `0x47BE8A = pop edi; or ax,0xffff; pop esi; add esp,0x14; ret` —— **建窗口那步 `call 0x4787c0` 全在这两道门的下游**。
  ⇒ `count>12` 既不是截断也不是翻页，是**连窗口都不建**，直接返回 `0xffff`(取消)，屏幕上什么都不发生。
- **用法**：逐节扫 `E8 rel32` 得到 **107 个**原生调用点，第 1 参数分布 = 2:47 / 3:16 / edi:13 / esi:10 / 4:5 / 5:3 / 6:2 /
  eax:2 / ecx:2 / 1:1 / 7:1 / 11:1 / ebx:1 / edx:1 / `dword ptr [0x550ea4]`:1(我们自己的桩)；靠循环喂数的站点自己压在 8
  (`cmp si,8 / jb` 之后 `push 8` @`0x47FE64`)。**没有一个原生站点 >12** ⇒ 原生控件不带分页，只能自己做。

**做法** — 只动 `child_menu.py` 的 `SRC_FOSTER` 与 M3c 数据区，批次数据一字未改：

| 件 | 值 / 写法 |
|---|---|
| `PAGE_KIDS` | **10** 个孩子一页；模块里 `assert PAGE_KIDS + 2 <= MENU_ITEM_MAX(12)` |
| 导航行 | 串池新增两行：`S_PREV=22`「上一页」/ `S_NEXT=23`「下一页」(共 24 行 x 24B)。一级表尾追：中间页 10+下+上=**12** 正好顶门、首页 10+下=11、末页 9+上=10、≤10 人时**不加任何导航行** |
| 帧变量 | `sub esp,0x38`；`+0x2C L_START` = 绝对起点(只 `add/sub PAGE_KIDS`，**全程没有乘除**)、`+0x30 L_MATCH` = 本次扫描的同城累计(**整池累计，不分页** ⇒ 用它判断还有没有下一页) |
| 扫描 | 换页 = 跳回 `cm_page`：把 行表计数 / 指针数组计数 / 同城累计 清零，`L_START` 保留，然后**整池重扫**。`cm_same` 两道门 = `L_MATCH >= L_START` 且 `L_ROWS < PAGE_KIDS`；`cm_count` 不管收没收都 `inc L_MATCH` |
| 下一页门 | `cm_scan_end`: `L_MATCH > L_ROWS + L_START`；上一页门 = `L_START > 0` |
| **分派靠哨兵不靠行号** | 两个导航行各自往 `SLOT_ARR` 写哨兵 `0xFFFE`(下一页)/`0xFFFD`(上一页)；弹窗返回后 `movzx edx, word[eax*2+SLOT_ARR]` → `cmp edx,0xfffe` / `cmp edx,0xfffd` 分派。**踩过的坑**：先用行号判定(第 `L_ROWS` 行=下一页、第 `L_ROWS+1` 行=上一页)，但"只有上一页"那种页里 上一页 恰好也落在第 `L_ROWS` 行 ⇒ 被当成下一页，起点一路加到空页。行号自证身份不可靠，改成行内哨兵 |

**验收** — `verify_children.py` **200 → 206 项，失败 0**（全部只读 exe 字节 + Python 仿真）：
- C23z5 `cmp [esp+0xc],0xa` 恰 1 条，且 `PAGE_KIDS+2 <= item_max`；
- C23z5b 哨兵两写一读、`cmp edx,0xfffe`/`cmp edx,0xfffd`、`add/sub [esp+0x2c],0xa` 各 1 条，且行号变量 `+0x34` 在面板里**一次都不出现**；
- C23z5c 页首复位点唯一 (`mov dword ptr [esp + 8], 0`)，两条导航分支各 `jmp` 回它一次(共 2 条)；
- C23z5d **分页仿真**：照 `SRC_FOSTER` 的四道门逐句重写的 Python 版，N∈{0,1,9,10,11,19,20,21,29,40} 要求 每页 ≤12 行、孩子 ≤10、`0..N-1` 全员可达且不重不漏、导航旗与实际页数吻合、逐行按哨兵分派落到的页号正确、首页无上一页 / 末页无下一页；
- C23z5e `CAP=1024 < 0xFFFD` ⇒ 真人槽永远撞不上哨兵；C23z5f 「上一页/下一页」两行从 exe 串池行 22/23 逐字节读回，且两张指针各写一次指向自己的行首。
- 回归：`verify_appear.py` / `tree_verify.py` / `preview_batch.py` 全过。big.exe **1383424B**，sha 已变（不再是 21e70ed4416c69d0）⇒ **实机请用这次构建**。

**效果** (`preview_batch.py` 的 ③ 现在报"要翻几页"而不是"选不到")：fam13 最多一城 6 人 ⇒ 没有导航行，**与改造前逐字节同行为**；
kids117 城66:19 ⇒ 2 页；all280 城66:29 ⇒ 3 页，另 6 座超 12 的城各 2 页。埋点语义未变：`PANEL_OPEN` 数面板开合(不数翻页)、
`KID_NOTSAME_CITY` 仍是"外城孩子被跳过"的次数。

埋点表从 `0x80`(32 槽) 抬到 **`0x100`(64 槽)** —— 表区 `0x2000..0x2100` 原本就有一段空隙，`KID_TAB` 仍在 `M(0x2100)`，
**没有任何区域搬动**；`build_big` 的 `regions`/`GROWTH_CTRS` 断言与 `verify_children` 的 C16g/C24q 都不再硬编码 `0x80`，
改读布局里的 `menu.cnt_bytes`（C16g 现在还额外断言 `表尾 <= KID_TAB`）。

**② `TKID_PAGE_KIDS` 构建档** (默认 **10** = 出货档；`TKID_PAGE_KIDS=2` = 试演档)
`PAGE_KIDS` 从常量变成 `int(os.environ.get('TKID_PAGE_KIDS','10'))`，`assert 1 <= PAGE_KIDS and PAGE_KIDS+2 <= 12`。

**两档都过全量静态**（同一套 207 项）：`10` 档 sha `cb8715e0…`，`2` 档 sha `af54acf3…`，都是 1383424B。
护栏：`verify_children` 的 C23z5 现在断言 **`_big_layout.json` 记的 `menu.page_kids` == 验收侧 `CM.PAGE_KIDS`**
⇒ 构建和验收用了不同的 env 会当场炸，不会"验过了但其实验的是另一档"。

**渲染陷阱补一条**：capstone 对 **<10 的立即数打十进制**，`PAGE_KIDS=2` 时 `cmp [esp+0xc], 0x2` 这种写法会 0 命中。

### 6.13 M3c-2 落地记录: 培养详情 GDI 面板 (五维条 / 成功率 P / 亲密) (2026-10-06，纯静态、不启游戏)

**为什么必须由面板自己画**：原生 `0x47BED0` 只能给「一串文字 + 选一项」，画不了五维条。
而 §6.7 尾定死的硬约束是 —— **面板上写的 P 必须就是桩掷骰用的那个 P**，否则"看着能中、实际没中"会被当成 bug。

**不重新造轮子** — 族谱面板(`tree_render.py`)那套 GDI 已经落在 `.fdata`(0x536000) 且跑通了，
本段只 `call` 这五个**已构建**的段，地址从 `tree_blobs.json` 取并在 `kid_panel.py` 模块加载时 assert：

| 复用段 | VA | 用在 |
|---|---|---|
| `resolve_api` | `0x53933A` | 惰性解析 27 个 API → `GDI_TAB`；**未解析时表内全 0，`call dword[TAB+n]` == `call 0` ⇒ 必须有 GDIOK 守卫** |

**★ 顺手修掉一个分页埋下的真 bug（会连带影响本轮面板）**

### 6.14 实机首个 bug: 回家菜单只画 2 项且卡死 —— 对话框实参顺序反了 (2026-10-06，实机取证)

**现象**：进自宅，菜单只有「休息 / 金库」两项、**没有「培养孩子」**，点击无反应（画面定住）。

**取证手段**（不启调试器，进程活着时直接拔现场）：
- `Wow64GetThreadContext` 采 11 个线程的 EIP → 主线程 39/40 阻塞在 `win32u`（GetMessage），
  **从未进入任何桩区间** ⇒ 不是死循环，也不是桩内死锁；`IsHungAppWindow = False`；
- `ReadProcessMemory` 埋点：`MENU_COUNT = 11`（钩子跑了 11 次）、`CMD_PUSH = 0`、
  `KID_NOTSAME_CITY = 0`、`GROWTH_PASS = 0` ⇒ 培养流程**一次都没走完**，连一级「选孩子」都没过。

**根因**：`0x47BED0`（原版对话框引擎）的实参顺序是 **`arg1 = 条目数`**（入口
`mov edx,[esp+4]` → `test dx,dx` → 拷贝循环以 `cmp ax,dx` 为上界）、`arg2 = 串指针数组`、
`arg3 = 样式`。而 `cm_hook` 记下的 `s_cnt=edi` 才是条目数、`s_flag=ecx` 是**样式**(2/4)，
却把二者传反了：

```asm
push ecx        ; ecx = cnt+1  -> 落到 arg3（引擎当样式用）
push edx        ; menu_ptr     -> arg2  ✅
push [s_flag]   ; 样式 2/4     -> arg1（引擎当条目数用）  ❌
```

于是引擎认为只有 **2** 个条目（样式值恰好是 2），只渲染前两项 ⇒ 截图里没有「培养孩子」；
同时样式参数变成 `cnt+1 = 3`，帧/命中区不对 ⇒ 点击无反应 = 卡住。
`cm_foster` 的四个子菜单（孩子/活动/教席/档次）一直是 `push n / push ptr / push 4` 的**正确**
顺序 —— 所以只有这一处错，也是它躲过自检的原因（自检没锁实参顺序）。

**修复**：`cm_hook` 改为 `push [s_flag] / push edx / push ecx`（末推 = arg1 = 条目数），
并在 `selfcheck_hook` + `verify_children.py` 新增 **C23b2** 把顺序钉死，防回归。

**教训**：静态自检只能验"形"，验不了"原生函数的实参语义"。凡是复用原生引擎函数，
必须先把**引擎入口自己的取参方式**反出来（本项目：`0x47BED0` arg1=条目数），再逐条对齐。

**三道门禁被拒时的提示串**（都是从 `MSG_STR` 按 `MS_*` 下标取的 GBK `[u8 长度][GBK][NUL]`）

| 条件 | 文案 | 门禁所在 |
|---|---|---|
| `f_cnt >= MONTHLY_CAP` | 这个月已经培养过了 | gate 1 |
| `byte[0x5205F2] + 天数 > 30` | 本月时日无多 | gate 2 |
| `word[0x51662E] < 天数×2` | 银两不够 | gate 3 |

**支付原语的口径**：`0x44E350(amt)` 内部走 `0x4A35C0 sat_sub(word[0x51662E], amt)`，
**它自己不查余额**（不够就静默扣成负数），所以 gate 3 必须在调用前自己比一次。

**进度表四行的换算**（`KD_VAL` 是真值，`KD_BAR` 是 0..100 的条长）

| 行 | 来源 | bar 换算 |
|---|---|---|
| 累计培养(次) | `KID_TAB[slot*12 + 2]` word | `×10` |
| 已养维度(维) | popcount(`KID_TAB + 4` bits) | `×20` |
| 距元服(月) | `age = 0x49A5C0(ent)`；`(15-age)*12`，已到龄则为 0 | `(180-n)*5/9` |
| 本月剩余(次) | `MONTHLY_CAP - [FOSTER.cnt]`，负数归零 | `×100 / MONTHLY_CAP` |

**反馈小框**：复用族谱那套 GDI 原语（`resolve_api 0x53933A / make_res 0x539414 / free_res 0x53965A /
wait_rel 0x5397A7 / pump 0x539953`），460×150，现场把孩子名拼出来（名表 7B + 姓表 7B，两段有界拷贝后补 NUL），
台词按 `(活动码 + MS_LINE0) × MS_STR_ROW` 从 `MSG_STR` 取，与活动一一对应（读书/读兵书/学剑术/习礼法/茶道/学算术/马屋打工/铁炮见习/随父见习/送寺修行）。

**验收**: `verify_final.py` **OK 12 / FAIL 0**（D 段新增：七段 ret、小框入口 = `0x5528F2`、
SetTextColor/TextOut 各 7 次）；`verify_children.py` **229 通过 / 0 失败**（顺带修正 6 条写成旧形态的期望，

#### 6.15a 实机第一个 bug：培养后「日期一路狂奔停不下来」 —— `0x4A0D50` 是 cdecl

**症状**：确认培养之后，游戏日期自己一直往前翻，停不下来。

**根因**：把推进天数那条原语的调用约定记反了。`0x4A0D50(hours, 1)` **不是** `ret 8` 的 stdcall，
而是普通的 **cdecl，调用方自己清**：

```
0x4B4075  push 1 / push 0x18 / call 0x4A0D50 / add esp,8     <- 79 个原生调用点绝大多数长这样
0x4CDBCF  push edi/ push 0x18/ call 0x4A0D50 / add esp,8
0x490D94  push 1 / push 2   / call 0x4A0D50 / add esp,8
```

原循环缺了 `add esp,8`：

| 轮次 | `pop ecx` 实际弹到什么 | 结果 |
|---|---|---|
| 期望 | 我们刚推进去的循环计数 | ecx 递减到 0 就收工 |
| 实际 | 残留实参 `0x18 (=24)` | ecx 每轮被重置成 23 ⇒ **永不结束**，还每轮漏 8B 栈 |

**修**：循环里补 `add esp,8`（见上向下 C23z3e），并加 `test ecx,ecx / je` 防 0 天时 `dec` 绕回 4G 次。

#### 6.15b 费用提示：点「就这么办」之前先告诉你花多少

串池新增 10 条（与 `ACT_DAYS` 静态对应，不用运行时拼数字）：`读书：3天/6金` … `送寺修行：6天/12金`。
确认框由 2 项扩成 3 项：

| 行 | 内容 | 选中后果 |
|---|---|---|
| 0 | 本次活动的 `活动名：N天/M金` | 放弃（纯信息行） |
| 1 | 就这么办 | **真的办**：`cmp ax,1 / jne cm_exit` |
| 2 | 再想想 | 放弃（与取消 `0xffff` 同结果） |

指针数组改成运行时拼（行地址 = `cost0 + act*24`，落 FOSTER 区尾 `cost_arr` 三槽）。

**回归工具**：`.rev/audit_callconv.py` 新增第二阶段 —— 原工具只查「别人调我们」的双清，

#### 6.15c 「培养后界面乱了」—— 一个池格式 + 一个居中公式 (2026-10-07 实机修复)

**症状**（用户截图）：黑框居中出现了、标题「森长可」却在框**左外侧**、框内全黑无字，
屏幕底部横着两串跨行糊字（「…马屋打工挣到钱了铁炮的声音真响」「习礼法：3天/6金 茶道：4天/8金 学算术：3天/6金」）。

**根因 1 —— 串池格式与解码不匹配**（主因）

| | 写入侧 `child_menu.msg_str_pool_bytes()` | 读出侧 `kid_panel.kd_m_frame` |
|---|---|---|
| 实际格式 | `[GBK][NUL][pad 到 24]` —— **无长度前缀** | 按 `[长度][GBK]` 解 |
| 代码 | `out += b + b'\x00' * (MS_STR_ROW - len(b))` | `mov ecx,[eax] / and ecx,0xff / inc eax` |

汉字高字节被当成长度：「打工挣到钱了」首字节 `0xb4` = 180 ⇒ TextOut 一次画 180 字节、连画 7~8 行串池；
提示行「点击关闭」首字节 `0xb5` = 181 ⇒ 同理。底部那两串糊字正好对应 行11..18 与 行15..22。

> **判据来自产物字节**（不是推理）：
> ```
> 11 off=264 raw=b4f2b9a4d5f5b5bdc7aec1cb0000...   <- 首字节 0xb4 是汉字高字节, 不是长度
> ```

**修**：两行改成 `push -1`（`cbString = -1`，GDI 自己找到 NUL）—— 池天生 NUL 结尾。
**不能反过来给池加长度前缀**：`cost_arr` / `deny_*_ptr` 是直接喂给原生对话框 `0x47BED0` 的，
它收 C 字符串指针，串首塞长度字节会被它当第一个字符显示。

> ★ **本工程有两套串池格式，禁止互抄解码**：
> - `kid_panel.STRINGS` → `[len][GBK][NUL]` **紧凑**；配 `movzx ecx,[eax]; inc eax`；面板走指针数组 `KD_STRTAB`。
> - `child_menu.MSG_STRINGS` → `[GBK][NUL][pad]`；配 `push -1`；因为同一份还要喂原生对话框。

**根因 2 —— 居中公式写成 `(wx0 + MW)/2`**

`kd_frame`（详情面板，正确）：
```
mov eax, [r_wx0] / add eax, dword ptr [r_wx1] / sar eax, 1
```
`kd_m_frame`（反馈小框，三处全错）：
```
mov eax, [r_wx0] / add eax, 0x1cc(=MW) / sar eax, 1
```
客户区宽 1280、`wx0 = 410` 时：正确中心 639，实际算出 435 ⇒ **整行文字偏左 200px，甩到黑框外面**。
（名字之所以还能看见，正是因为它在框外。）修：三处统一 `add eax, dword ptr [r_wx1]`。

**根因 3 —— 自查拦下的守卫写小**（未进产品）

新加的槽越界守卫原本写 `cmp [msg_slot], 0x40`。但本批孩子实体在 **槽 463..476**
（`CHILD-PRELOAD: 批次 fam13 = 14 人 (槽 463..476)`），姓名表按槽直索引（4578B / 7B = **654** 行）。
守卫写 0x40 ⇒ `kd_msg` 头两行就 `jae` 走人 ⇒ **反馈框永远不弹**，且症状是"什么都没发生"，比乱码更难查。
修：`NAME_TAB_ROWS = 654` / `SLOT_MAX_MSG = NAME_TAB_ROWS`。

**顺带核准单位**：截图「所持金 **0贯200文**」说明 `word[0x51662E]` 单位是**文**（1 贯 = 1000 文）。
`GOLD_PER_DAY = 2` 是照抄原生修行口径（§0.2「每日 2 金」，字段同源），**数值不动**；
只把文案 `…天/…金` → `…天/…文`，拒绝框「银两不够」→「所持金不足」（与游戏 UI 用词一致）。

**新增防御**

| 层 | 内容 |
|---|---|
| `kid_panel.selfcheck_panel` | `and ecx,0xff` == **0**；`push -1` == **2**；`add eax,[wx1]` == **5**（详情 2 + 小框 3）；`add eax,MW` == **1**（只允许 `wx1 = wx0+MW-1` 那处） |
| `verify_children.py` | **C23z3g** 无长度前缀解码 / **C23z3h** 三处居中按字节 `03 05 <wx1_va>` 计数 / **C23z3i** 槽守卫 == 姓名表行数（读 `cmp eax,imm32` 立即数） |
| `kd_msg` 入口 | 两道守卫：`msg_act < 10`、`msg_slot < 654` |

**验收**：`verify_final.py` **12/0**、`verify_children.py` **237/0**、`audit_callconv.py` **30 处符合 / 0 异常**。
`TAIK2W95_big.exe == TAIK2W95_big_m5.exe`，md5 `80276782a1aa4f8263fc5550c085019a`。

**教训**：「屏幕上出现不该有的文字」先怀疑**指针/长度**，别先怀疑绘制。
这次两个症状（糊字 + 空框）分别是**一个池格式**和**一个居中公式**，与 GDI 参数无关。

### 6.15d 实机第二轮三个 bug 一起修（2026-10-07，实机取证）

用户原话：「每次进入城，然后回家，结果点击培养孩子就不行了，非要等下一个月。然后会弹出一些大名的对话后，孩子才出现。最后培养后给出的界面，空空如也。」

| # | 症状 | 根因 | 修法（落机器码） |

| ① | 进城→回家后点「培养孩子」名单是空的，要等下个月才恢复 | 名单按「孩子 `word[+0x24]` == 主角 `word[+0x24]`」筛；而**孩子随父居住**的 `place_child` 只有两个调用点：`make_child` 末尾、以及 `child_pass` 的**月钩 `rearm`**。主角一移动，孩子的城还挂在旧城，名单就空到下次月钩 | `cm_foster` 开头（`0x550FE8`）**复跑一次 `child_pass @0x54C800`**：该桩入口 `push ebx/esi/edi/ebp`、`done` 处原样 pop，**无实参、幂等、自包含**，其 `rearm` 路径末尾正好调 `place_child`，于是名单永远反映父亲此刻的所在地 |

**新增防御**

| 层 | 断言 |

| `kid_panel.selfcheck_panel` | `and ecx,0xff` == **0**（不得把首字节当长度：这个池没有长度前缀）；`push -1` == **0**（cbString 绝不能传 -1）；`cmp byte ptr [edi+ecx],0` == **2**；`cmp ecx,行宽` == **2** |

| `verify_children.py` | **C23z8 判据换血**：四级弹窗不再按「紧邻前一条是 `push ecx`」认（实测四级收尾分别是 `push eax` / `0xb` / `6` / `5`，没有 ecx），改为**按源码常量核**：`{eax, len(ACTS)+1, len(TEACHERS)+1, len(TIER_NAMES)+1}`，这样新增的空名单框（`push 1`）与三拒绝框（`push 1`）、确认框（`push 3`）都不会混进来 |

**教训**

1. 「界面空空如也」和「界面糊成一片」是**同一个坑的两面**：池格式与 `cbString` 必须成套——`[len][GBK][NUL]` 池配套「读 `row[0]` 当长度」，`[GBK][NUL][pad]` 池配套「**自己数到 NUL**」。两套池混用解码器必然出事，且第二次踩同一条头注。
2. **调用原生引擎函数的副作用要当成 API 的一部分记下来**：`0x4A0D50` 不只是「推天数」，它还会派发每日事件。凡是"先给玩家看反馈、再推进世界"的顺序，反馈必须排在它前面。
3. 「数据只在月钩刷新」这类惰性同步，一旦被 UI 直接读就会表现为"要等一个月"。修法是**在读之前主动跑一次那个幂等的刷新桩**，而不是把刷新逻辑抄一份进 UI。

## 7. 风险

- **R6** `0x4600D0/0x45FEB0` 的 arg 布局本轮已拆 (`0x4600D0(idx, 实体)`，分支内 `[esp+8]` 因 `push esi` 变成第二个参数)；
  但 `0x45FEB0(mode, 实体, 减项)` 的概率门只拆到"分母 = `0x10/0x14` 与 `[esp+0x28]` 之差"，
  **M3b 直接用 `0x4a2f80..0x4a3000` + 自己的 `rand(100)` 门**，不去依赖 `0x45FEB0`，把不确定性关在门外。

    (家臣之子、族谱收录的养子都可教) ⇒ **不需要"收养/血缘"门**，只要 `word[ent+0x25] == 主角之城` 且状态字是儿童档。
    血缘只影响 **T 加成** (§2.4: 亲生父母教导有亲密度加成，外人教无) 与 **亲密度增速**，不影响可用性。

### 8.1 「回家」菜单已实地钉死 (2026-10-06 第二轮，用户指正后重做)

**用户实测更正**: 原生**确实有**「回家」——在自己主城时命令栏有「回家」，点开就是 **休息 / 金库 / 与宁宁交谈 / 武将休息室 / 离开 / 探病 / 与阿桢谈话** 这张菜单。
(此前 §8.1 的"原生没有可进入的主角之家"是错的：我只扫了场所名池 `0x508040` 的立即数引用为 0 就下结论，那是纯显示表、被计算地址索引，**不能证明语义不存在**。教训: 静态 xref 只能证明"没有硬编码"，不能证明"游戏里没有"。)

已把这张菜单整条拆穿 (脚本 `.rev/xref.py dis` / `a_call.py`，锚点全部从真指令边界起):

| 环节 | 地址 | 要点 |
|---|---|---|
| 回家命令派发 | `0x4cb86d → call 0x4cbab0(ebx, ..., esp+0x14)`，其内 `0x4cbab6 call 0x4cb6d0` | 门: `word[ebx+0x2c] & 0x700 == 0x100` 且 `si==1`，`ebx` 在槽 `0..0x171` 里扫 ⇒ "回家"= 主角本人所在城；**这层不用动** |
| 菜单循环体 | `0x4cd320(esi, edi)` | 循环: `0x4cd339` 起，`0x4cd367 call 0x4cd480` 弹菜单，取消/离开退出 |
| **菜单构建器** | `0x4cd480` (`sub esp,0x24`) | 见下 |
| **通用菜单对话框** | `0x47bed0(count, dword* 串指针数组, flag, 0, 0)` → `ax`=选中序号，`0xffff`=取消 | 原生现成件，**不需要自己画 UI** |
| 指令码→处理 | 跳转表 `0x4cd460` 共 7 项 (码 0..6)，`0x4cd38e cmp eax,6 / 0x4cd391 ja 0x4cd455`(退出) / `0x4cd397 jmp [eax*4+0x4cd460]` | **好消息**: `0x4cd47c` 正好是表尾之后的 4 字节对齐 NOP (`90 90 90 90`，紧贴 `0x4cd480` 函数头) ⇒ 它是**第 8 个表项的空位**，白送 |
| **查表前的两道预判** (M3c 复核补) | `0x4cd36f cmp ax,0xffff / je 0x4cd41d`、`0x4cd381 cmp ax,4 / je 0x4cd41d`，之后才 `0x4cd38b movsx eax,ax` | ⇒ 取消必须回**全宽 -1**；码 4「离开」根本到不了表；**`movsx` 会把 0xffff 变成 -1 也是这层先拦掉的原因** |

构建器逐项规则 (设 **E = 构建器入口 esp**，即 ret 地址所在；`sub esp,0x24` + `push ebp/esi/edi` ⇒ 帧内 `esp = E-0x30`；
码表 base = `E-0x24`(=`[esp+0xc]`)，串指针数组 base = `E-0x18`，计数在 `edi`):
- `codes[0]=0` 休息 **恒定存在**；
- `!(byte[0x516638] & 4)` ⇒ `codes[1]=1` 金库，`edi=2` (该位被置时金库项整条消失，`edi` 停在 1)；
- `loc = (word[0x520604] >> 12) & 3`：`0` ⇒ 追加 `2` 与宁宁交谈；`1` ⇒ 追加 `6` 与阿桢谈话；`2/3` ⇒ 不追加；
- `arg1 != 0` (`[E+4]` = `0x4706b0(主角,1,1)` 的结果) ⇒ 追加 `3` 武将休息室；
- `arg2 != 0` (`[E+8]` = `0x4706b0(主角,2,1)` 的结果) ⇒ 追加 `5` 探病；
- 最后恒定追加 `4` 离开 ⇒ **最多 6 项**。
- 串地址 = `0x50CAE8 + 码*11` (GBK 定长 11B，`lea ebp,[eax+eax*4]` / `lea eax,[eax+ebp*2+0x50cae8]`)；
- `flag = ([E+0xc] != 0 ? 4 : 2)`；
- 调用约定: **cdecl、5 次 push、`add esp,0x14`** ⇒ `0x47bed0(count, 串指针数组, flag, 0, 0)` → `ax` = 选中**序号**，`0xffff` = 取消 (内部 `0x47be00`)。
  ⚠ **一屏最多 12 项** (M3c 落地时按字节复核，此前写的"最多 40 项"是错的): 真正的门在内层 `0x47BE09` `test di,di / jle 0x47be8a` +
  `0x47BE0E cmp di,0xc / jg 0x47be8a` ⇒ `count ∈ 1..12`，越界直接返回 `0xffff`(=取消)。
  `0x47BED0` 里 `sub esp,0xa0` 的拷贝循环只钳到 `cmp ax,0x28`(40)，那**只是拷贝上限**，不是可用项数。
  ⇒ 我们的回家菜单最多 6+1=7 项；面板选孩子已改成分页(一页 10 人 + 导航行，总数恒 ≤12) ⇒ **不再"静默少列"**，详见 §6.10。独立子菜单实测用 flag=4。
- 返回后构建器在 `0x4cd583` 用 `mov ax,[esp+eax*2+4]`(esp 已回到 E-0x28 ⇒ 基址正是 `E-0x24`) 把**序号翻译回指令码**后 `ret`。

**⚠️ 栈容量硬约束 (决定了实现形态，两处都装不下第 7 项)**:
- 串指针数组 base = `E-0x18`，可用区 `E-0x18 .. E` 恰 24B = **6 个指针** ⇒ **第 7 个指针正好覆写返回地址**；
- 码表 base = `E-0x24`，第 7 个 word 落在 `E-0x24+12 = E-0x18` ⇒ **正好压在 `ptr[0]` 上**。
⇒ **不能就地追加，也不能只搬数组**：MOD 侧必须把 **码表 + 指针数组两份都拷出来**，并且**绕开 `0x4cd583` 的原生翻译**。

**落地方案 (M3c，两处小补丁 + MOD 侧收尾) —— 2026-10-06 已按此建成，实做差异见 §6.7**:
1. **断点 = `0x4cd563`** (`push ecx` 处，`E9 rel32` 5 字节正好盖住 `push ecx/push edx/push edi` + call 的前 2 字节)。
   cave 入口 `esp = E-0x38` (两条 `push 0` 已执行)，据此取 `codes base = esp+0x14`、`ptr base = esp+0x20`、`count = edi`。cave 做:
   ①把 `count` 个 dword 串指针 + `count` 个 word 码**拷进 MOD 私有区** (`M(0x5320)` 64B 指针 / `M(0x5360)` 32B 码；已随 §5.1 M3b-1 定稿)；
   ②指针表尾追加字符串 **"培养孩子"**，`count+1` 后进 ③；
   ③**只压 3 个参数** (`push flag / push 我们的指针表 / push count+1`) → `call 0x47bed0` → `add esp,0x14`；
   另两枚 `0` 由原生在 `0x4cd551/0x4cd557` 已经压好的两枚 `push 0` 提供 (它们在我们的 jmp **之前**，原地留在栈上，不用重压)。
   ④`ax == 原count` ⇒ 最终码 = `7`；否则最终码 = 我们的 `codes[ax]` (0..6)；`0xffff` ⇒ 走取消；
   ⑤跳到 **MOD 收尾**: `pop edi; pop esi; pop ebp; add esp,0x24; ret` (入口时 esp 已是 E-0x30，与原生的 `0x4cd581..0x4cd58c` 逐条同构)，`ax` = ④ 的最终码。
   —— 这样"加一项"完全不碰原生数组边界、**不受 11 字节等长串池约束** (对比 §1.4 的修行菜单方案，风险从"高"降到"低")；
   取消/其余 6 项的行为与原生的差别只在"翻译由我们做"，可用 `verify_children.py` 逐分支静态核对。
2. **派发 = 只用 5 字节 (1 字节改立即数 + 4 字节填表尾 NOP)**:
   ①`0x4cd390: 06 → 07` (让 `cmp eax,7`，码 7 不再是"越界→退出")；②`0x4cd47c: 90909090 → <我们的处理程序 VA>`。
   ⇒ 我们的处理程序与原生 6 个入口**同构同上下文** (`esp` 等于 `0x4cd397` 时的值，`esi`=主角、`edi`=第二参数、`ebx/ebp` 原样)，
   照抄原生形状: `push edi; push esi; call child_raising_panel; add esp,8; jmp 0x4cd339`(回菜单) 或 `jmp 0x4cd455`(退出)。
   原生 0..6 六个处理 (`0x4cd590` 休息 / `0x4cdce0` 金库 / `0x4cdf80` 与宁宁·阿桢 / `0x4cbcb0`+`0x4ce4e0` 休息室 / `0x4ce3b0` 探病) **逐字节不动**。
   (已核: `0x4cd47c` 在全镜像里 0 处被引用，覆盖 NOP 对齐填充安全。)
3. **"培养孩子"面板本身**仍用我们已跑通的 `.fdata` GDI 面板 (方案 A 的渲染层)，因为它要显示五维条/概率/亲密，原生对话框给不了；
   原生 `0x47bed0` 只用来选**孩子**（列表项 = 同城所有孩子的姓名串，见 D4-a）。⇒ 这里其实可以用**第二次** `0x47bed0` 调用直接列孩子名单(每项一个姓名串指针, 上限 40 ⇒ 一屏内孩子够)，选中后再开 GDI 详情面板。
