# 儿童态配方 (M1 产物) —— 在场、不参与 AI、会长大的状态组合

> 唯一目的: 把「开局就把没登场的孩子放进世界, 且不被引擎的 AI/名单/死亡/退隐机制吞掉」
> 这件事, 收敛成一组**引擎原语调用序列**。M2 预载器只允许实现这份配方, 不得自创状态字节。
>
> 证据基座: `.rev/probe_child.py` → `.rev/_child_probe.txt` (1187 行) / `_child_probe.json` (41 键)。
> 两法互证: A) 失步重同步线性反汇编 0x401000..0x4FA000, 366,734 条 / 99.99% 覆盖, 51 次重同步;
> B) ModRM 字节型扫描全镜像 0x401000..0x533000 (A/B 差集已逐点解释)。所有结论以 A∩B 为准。
> 本文所有地址为 clean_dump.bin (=TAIK2W95_family.exe 语义) VA; big.exe 里池基址类常量已被
> P1 重定位到 0x53C000, 47B 步长与所有字段偏移不变。

---

## 0. 一句话配方

**真实体 + 在场(bit15=0) + 排除(bit4=1) + 待期倒数位(nibble=0xb, 即 getter≠0xff) + 无主(主君=0xffff,
身分码=0) + 登场标志[oid]=1 + MOD 儿童位图记账 + 每月复臂。**
年龄一律走原生 `0x49A5C0`, **不引入 MOD 历法**。

---

## 1. 引擎给的三个免费保险 (为什么这套状态是安全的)

### 1.1 空缺槽永远抢不走孩子
登场例程 `0x4A4D10` 的 A 步 (扫池找空槽) 收入条件为
`nib_get != 0xff 且 > 0` **并且** `bit15=1(不在场) 且 bit7=0` (见 build_big 4i 注 + `_child_probe.txt` K3)。
孩子的 `bit15=0` ⇒ **永远进不了空缺槽表** ⇒ 不会被 `0x47F7B0(slot,oid)` 覆写。
(空缺槽由 big.exe 的 `ensure_queue` 只在池尾 354..369 武装, 且只有 bit15=1/bit7=0 的 0x808F 槽会被武装。)

### 1.2 nibble≠0xff 同时关掉两把刀
`nib_get 0x49A610`: `al=[ent+0x2c]&0xf; al>=0xc ? 返回 0xff : 返回值`。
每月每人的实体事件派发器 `0x4A41B0` (唯一调用者 `0x4A6F3E`, 按 `slot%30` 错峰遍历整池——
big.exe 已把这批 `0x172` 界抬到 CAP, 所以**扩展槽同样被访问**) 依次调用:

| 站点 | 例程 | 语义 | 前置条件 |
|---|---|---|---|
| 0x4A41CF | `0x4A4740` | **自然死亡抽签** (1/10 每月) → 命中则 `nib_set(6+rnd)` + `bit4=1` (0x4A4872/0x4A4891) | `nib_get==0xff` (0x4A477F/84) **且** `age > thr` |
| 0x4A41D8 | `0x4A4910` | **随机解禁: `push 0; call 0x49A6D0` 清 bit4** (在野复仕) | bit4=1 **且** `nib_get==0xff` (0x4A491D/22) **且** `rnd(5)!=0` |
| 0x4A41E1 | `0x4A4940` | 退隐 → `bit4=1` | `test [ent+0x2c],0x90` 已置位则跳过 |

⇒ **孩子把 nibble 设成 0xb (非 0xff) 就同时免疫「死亡抽签」和「bit4 被随机清掉」。**
单靠 bit4 是不够的: `0x4A4910` 会以 4/5 概率清掉它 (证据: `0x49A6D0` 的 9 个调用点里唯一的清位点
`0x4A4939`, 上面这张表)。
nibble 为何能常驻: 全镜像只有 6 个 `nib_set(0x49A6B0)` 调用点, 其中每月递减点 `0x4A4D61`
在 big.exe 4i(a) 已冻结成埋点 ⇒ 不设不回退, 稳定。

### 1.3 年龄门槛天然保护未成年人
`0x4A4740` 的年龄门 (0x4A47BA..0x4A47D4):
```
thr = 10 * ( ((word[ent+0x1b] >> 13) & 7) + 2 )      # 20..90, 取 BSDATA 打包位
ecx = ent; call 0x49A5C0 ; cmp ax, di ; jbe 跳过
```
最小门是 20 岁 ⇒ **15 岁以下的孩子即便 nibble 被人改成 0xff 也不会被抽死**; 元服后 (15..19) 仍在保护带内。

## 2. 落地序列

### S1 实例化 (唯一合法的孩子出生方式)
照抄原生登场路径 `0x4A4E88` 内层 (0x4A4F05..0x4A4F40):
```
push slot        ; arg1 = 槽号 (edi 侧)
push oid         ; arg2 = BSDATA oid
call 0x47F7B0    ; cdecl; ecx 入口值不被使用(函数首句即 mov ecx,0x524a20)
```
`0x47F7B0` 做三件事 (逐条实测): `oid*59` 定位 BSDATA 记录并把游标写进 `[0x522C98]`;
用 `0x47FA40`(字节)/`0x47FA60`(字) 顺序把记录抄成 47B 实体 (`ent = 池基 + slot*47`,
`lea esi,[edi+edi*2]; shl esi,4; sub esi,edi`); **同时写姓表 `[槽*7 + 0x521AA8]` 与名表 `[槽*7 + 0x520660]`**
⇒ 头像/姓名/族谱全都真能显示, 满足「生成的人物要实实在在能在游戏里有的」。
状态字取自 BSDATA 记录 ⇒ 生来是活人态。

调用约定备忘 (全部实体访问器同构: `ecx=实体指针; push 参数; call`, `ret 4`):

| 原语 | 地址 | 作用 |
|---|---|---|
| 年龄读 | `0x49A5C0` | `eax = (1560+[0x5205f0]) - (1490 + (byte[ent+0x1b]&0x7f)) + 1` |
| 年龄写 | `0x49A5E0(age)` | 只翻 +0x1b 的 bits0..6 ⇒ **bit7 与字高字节是 MOD 自由区** |
| nibble 写 | `0x49A6B0(v)` | xor 技巧只改低 4 位 |
| nibble 读 | `0x49A610` | ≥0xc 视为 0xff |
| bit4 排除 | `0x49A6D0(1/0)` | set `or byte[+0x2c],0x10` / clear `and word[+0x2c],0xffef` |
| bit7 无效 | `0x49A738/0x49A73F` | (不用, 见 §4) |
| 身分码 bits8..10 | `0x49A7E0(code)` | `and 0xf8ff; or code<<8` (0无…7大名) |
| bit15 在场 | `0x49A860(0)` | clear = `and word[+0x2c],0x7fff` |
| 元服初始化 | `0x4A4FC0(ent)` | 按 身分码/主君 挂载; `test byte[+0x2d],7` 分流 |
| 新人 init 配方 | `0x440D20` | 引擎自己的「新活人」访问器序列 (身分码0/主君0xffff/体力100/nib 0xff/bit15=0) |

### S2 设儿童态 (S1 之后立刻执行, 顺序无关, 全用原语)
1. `0x49A860(0)`  — bit15=0, 在场/存活 (§1.1 的保险由此而来)
2. `0x49A6B0(0xb)` — 待期倒数位, 非 0xff ⇒ 免疫死亡抽签 + 免疫 bit4 随机解禁 (§1.2)
3. `0x49A6D0(1)`  — bit4=1 排除: 名单构造器 `0x419416` `test [ent+0x2c],0x90` 直接跳过;
   访问器 `0x408DC0` (`test [eax+0x2c],0x10` → 返回 NULL, 仅 1 个调用点 `0x408DAE`) 使孩子不落入家臣解析
4. `0x49A7E0(0)`  — 身分码=0 (无役职); `word[ent+0x2a] = 0xffff` — 无主
5. `byte[0x519288 + oid] = 1` — **登场标志**: 实测全镜像仅 4 个引用点 (K5), 唯一写点 `0x4A4F1F` 置 1,
   **没有任何代码清它**; 且它被原生存/读档函数直接序列化 (`0x47F3EE`/`0x47F63E` push 表基址)。
   ⇒ 置 1 后原生每月登场通道 `0x4A4DBE cmp byte[ebx],0 / jne skip` 永久跳过该 oid, 不会重复生成同一个人。
6. MOD 位图记账: `M(0x100)` 起的 1024-bit 儿童表 (.edata MOD 私有区, 见 `_big_layout.json`),
   位=1 表示该槽是 MOD 孩子。**孩子身份的真相源是位图, 不是状态字节** —— 状态字节会被引擎动, 位图不会。

生年 (+0x1b) 由 S1 从 BSDATA 带来, 不动 ⇒ 年龄是真实虚岁, 无需 MOD 历法。

### S3 每月复臂 + 保存链尾重放 (M2 已实现: `.rev/child_stub.py` 263B 桩)
big.exe 有两处钩子, 共用同一块幂等 `child_pass`:
- **月钩** `0x4A4CC5` (`call 0x4a5370`, 正好在 4i(d) 的 `ensure_queue`→登场例程 `0x4A4D10` 返回之后)
- **保存侧钩** `0x47F71F` (`call 0x47f2a0`) —— ★2026-10 方向定论更正: 它在 `0x47F5C0` 里，而
  `0x47F5C0` 只被**保存**派发器 `0x47FC10`(调用点 `0x47FC40`) 调用；链内 `0x47F6AF` 调的是
  **写**链 `0x47DF00`(实体→档)、`0x47F63E` 写登场标志 —— 即"整条保存链跑完、原生句柄还没关"。
  当初把它当"载入后重放"是方向读反了(见 `child_save.py` 头注五证)。后果与现状:
  读档后扩展槽不在此重放，靠**月钩**下一月到位；"读档即恢复"改由 **M6 影子档**在载入派发器
  链尾 `0x47FBEE` 整体回填；保存时多跑一趟 `child_pass` 无害(在岗只复臂+随父搬家，不重跑
  `init_stats`)，且顺序在 M6 写影子档之前 ⇒ 影子档拿到的就是这趟之后的状态。

两处都是 `pushad / call child_pass / popad / jmp 原callee` (pushad+popad 连 esp 一起还原,
站点自身的 push 与 ecx 不受影响)。`child_pass` 逐条走排程表, 四条分支:

| 分支 | 判据 | 动作 | 埋点 |
|---|---|---|---|
| 新槽 | 位图未认领 且 `状态&0x8080==0x8080` (静态空槽) | `make_child` = S1+S2 全序列 | `CHILD_PRELOAD` |
| 我方+在岗 | 位图已认领 且 bit15=0 | 只复臂 (`nib_set(0xb)`+`bit4=1`) | `CHILD_REARM` |
| 我方+不在场 | 位图已认领 且 bit15=1 (池被重置过) | 重新 `make_child` | `CHILD_PRELOAD` |
| 他人占用 | 未认领 且 不是 0x8080 | 跳过, **绝不覆写别人的槽** | `CHILD_SKIP` |

复臂的必要性: 若某天引擎 (或后续 MOD) 把 nibble 置回 0xff, `0x4A4910` 就能在 `slot%30` 的那个月清掉 bit4;
复臂把最坏暴露窗口压到「同月之内」。`CHILD_REARM` 应当**长期为 0** —— 非 0 就说明有代码在动孩子的 nibble, 要查。
`CHILD_SCAN` 每月 +1 = 月钩活着; 读档/切剧本后 `CHILD_PRELOAD` 会再涨一轮, 那是「重放式持久」的预期行为。

### S4 元服 (M4 已建成, 到龄自动 —— 本节按 big.exe 字节重写, 旧稿的 `call 0x4A4FC0` 是错的)

成长桩 `0x54CA00` 月钩里, 每人每次进桩先读年龄 (`0x49A5C0`), `虚岁 >= 元服线` (`KID_AGE_GENPUKU`, build 默认 15)
就进元服支 (`0x54CB52..`)。**一次性门 = 桩入口那句 `cmp al,0xb`**: 元服支第一件事把低 nibble 拧成 0xf,
此后这个孩子再进桩就在入口被跳过 —— 所以 KID_TAB+10 的归属码只是给面板/D2 显示的**读数**, 不是门
(拿它当门会把「重开剧本/影子档 MISS 后 nibble 回到 0xb」的孩子永久卡在 15 岁儿童态)。

1. `0x49A6B0(0xff)` — 低 nibble 0xb -> **0xf** (xor 掩法只碰 bit0..3, 高 12 位不动; 原生 370 人里 369 个成人都是 0xf)
2. `0x49A6D0(0)`     — 清 bit4 排除 ⇒ 从下个月起进引擎名单 (传 0 走「清」, 传非 0 走「置」)
3. **归属** (两条路, 全是引擎原语, 桩自己只写归属码):
   - 有父 且 父过四道门 (`bit15=0` / `身分码!=0` / `城<0xc8` / `国<0x31`) => `push 父; push 本人; call 0x4A5100; add esp,8`
     (cdecl 2 —— 与 `0x4A5290` 内部那一发同形同序, 本人总在最后一个 push)。它替我们做: 国的城写手把**本人国/城=主人国/城**、
     `0x4A0540(城记录, 本人, 1)` 挂进城家臣链表、`0x49A730(0)` 清 bit7、身分码 0 -> 1(家臣)、+0x12/+0x13/+0x16 归位;
     **不写主君 +0x2a** (引擎自己挂的家臣也不写, 我们照旧)。返回 0 => 立刻改走下一条, 不会静默失败。
   - 否则 `push 本人; call 0x4A5290; add esp,4` — 本国国主 = 表 `0x5179b8` 步长 18 取 `word[+4]`;
     槽上界那句 `cmp ax,0x400` 已被 P2 从 0x172 抬到 CAP ⇒ **扩展槽人物当国主也挂得上**;
     返回 1=挂上国主(归属码 2, 身分码 1) / 0=浪人化(归属码 3: 身分码:=0、国:=0xff、城=0x49F940(所属)-0x38)。
   - 随父成功且**父身分码==7** 再补一发 `0x49A800(1)` (bit11 大名一族) —— 照 `0x4A5220/0x4A5290` 里同一段 `and eax,0x700` 判定。
4. 埋点顺序 (身份式由此结构保证): 支首 `GROWTH_FREEZE`+1 -> `GROWTH_PUKU_MOUNT`+1 (随父/国主两路各一) 或 `GROWTH_PUKU_RONIN`+1
   -> 汇合 `CHILD_GENPUKU`+1 ⇒ `FREEZE == CHILD_GENPUKU == MOUNT + RONIN`。
5. **不拉属性**: 元服是身份转换不是练级, 五维已由 M3b-2 的自然保底按月爬到成年档; 也**不清 MOD 儿童位图**
   (面板按位图认领孩子, 影子档按位图整段存回 —— 元服后仍要能被认出来)。

元服后状态字预测 (逐孩已算进 `_child_expect.json`, 手测用 tkwatch 对):
`随父 = (fin & 0xF8E0) | 0x010F [| 0x0800 若父=大名]` ; `挂国主 同上不带 0x0800` ; `浪人 = (fin & 0xF8E0) | 0x000F`
(0xF8E0 = 除低 nibble/bit4/身分码 之外全保留 —— `RANK_SET` 的掩是 0xF8FF, 只覆写 bit8..10, 位 11..14 原样留着)。

**不动原剧本登场**: 元服阈值由 MOD 自己判 15 岁, 不碰 `0x4A4F1A` 的 0x172 界、不改 BSDATA 登场年日程。

## 3. 槽位选择与持久化边界

- 存档/剧本写出器 `0x47DCE0` 与读入器 `0x47DF00` 各自只有 1 个调用点 (`0x47F45B` / `0x47F6AF`),
  且**逐槽只循环 0..369** (P2 特意保留这 6 个 `0x172` 点当文件格式锚)。
- ⇒ 孩子放 **370..CAP-1 扩展槽**: 同一局内完全有效, 但存盘后读档=实体消失 (登场标志位是原生存档的, 会留着;
  人没了)。这是已知代价, **M6 sidecar `TKMODSAVE.DAT` (钩 `0x47F45B`/`0x47F6AF`) 才是正解**。
- 放 0..353 会挤掉原生存档人物 ⇒ 禁止 (也违反「原剧本登场相关先别动」)。
- 待登场保留槽 354..369 是 4i(d) 的武装区, 孩子不得占用。

## 4. 明确不用哪些方案 (探针否掉的)

| 方案 | 为什么不用 | 证据 |
|---|---|---|
| `+0x2e bit2` 当永久排除位 | 名单构造器 `0x419473` 每次都 `0x49A8C0(1)` 置它, 20 处测它 ⇒ 瞬态, 引擎自管 | K2 +0x2e 段, 0x419469/0x419473 |
| `+0x2e bit0` 当排除位 | 33 个引擎调用点读写, 语义是「事件占用」 | `0x49A880` 簇 xref |
| `bit7=1` (0x808F 式占位) | 排除力更强但会让孩子在 `test [ent+0x2c],0x80` 的各个显示/统计循环里整体隐身, 违背「实实在在能在游戏里有的」 | 0x41D09D / 0x41E5BD / 0x462EDF / 0x4A478C / 0x4C13C2 |
| `bit15=1` (不在场) | 立刻变成空缺槽候选, 被登场通道覆写 | §1.1 |
| MOD 自维护年龄/日历 | 原生 `0x49A5C0` 已是 `(当前年 - 生年 + 1)` 且有 13 个消费者(含显示) | K1 |
| 手写 47B 实体字节 | 绕开 `0x47F7B0` 就丢掉姓/名表与 BSDATA 档案一致性, 族谱/头像会错位 | S1 |

## 5. 遗留风险 (M2 起持续更新, 开工前必读)

- **R1 已闭合 (M2)**: 原生配对代码 `0x4A4F1A` 算实体指针的槽界 `cmp si,0x172` 早已被 P2 抬到 CAP
  (big.exe 现为 `66 81 FE 00 04` = `cmp si,0x400`), 所以扩展槽被武装时 `0x4A4FC0` 不会收到 NULL 实体。
  该事实现在有两道闸: build_big 4j 的构建期断言 + `verify_children.py` 的 C8。
- **R2 nibble=0xb 的语义外溢**: `nib_get` 有 21 个调用点, 非 0xff 值在它们眼里是「有事件待期」。
  死亡/退隐/解禁三处已被 §1.2 证明是跳过方向; 其余点若出现异常显示, 首选退路是
  「nibble 保持 0xff + 每月复臂 bit4」(牺牲 §1.3 的免疫, 靠复臂兜底)。
- **R3 4i(a) 冻结倒数位的副作用**: 全体倒数位都不再递减 ⇒ 原生死亡流程停在
  `bit4 + nib<0xff` 的中间态。这正是孩子免疫的来源, 也是测试时看到「该死的人不死」的原因, 属已知取舍。
- **R4 两枚姓名表按 *槽* 索引, 且极性反直觉 (M2 已实测锁死)**:
  `0x520660 = 名表`, `0x521AA8 = 姓表`; big.exe 里搬到 `0x547C00 = 名表` / `0x549800 = 姓表`。
  索引是**槽号**不是 oid (真机 354 槽全对上: 槽 k = 第 k 个在场 oid)。
  ⇒ 同一 oid 换槽会留旧名, 扩展槽复用前先清零那 7B; 更要命的是**写名字时必须 姓→姓表**:
  `build_big.py` 4f) 早先按变量名(`SUR_*`)直觉配对, 把 92 个休眠名写反了表, 现已修
  (`verify_children.py` C10a/C10b/C11 三条断言守住)。注意仓库老工具 (`dump_ents.py`/`tkwatch.py`/
  `build_big.py`) 的 `SUR_*`/`GIV_*` 变量名与语义**相反**, 沿用是为了地址口径; 真值看
  `_big_layout.json` 的 `given_tab_va` / `surname_tab_va`。
- **R5 记录→实体的字段映射**: `ent[k] = rec[k+12]` (k=8..46), `ent[2..7]` 由引擎另置。
  故 状态字 `ent+0x2c ← rec+0x38`, 主君 `ent+0x2a ← rec+0x36`, 生年打包字 `ent+0x1b ← rec+0x27`。
  预载后的状态字可直接预测: `(rec[0x38] 读 u16 & 0x7870) | 0x1B`, 只剩位 5/6/11..14 继承自记录
  (逐人数值见 `_verify_children.txt` 末尾表 + `_child_expect.json`)。
- **R6 元服是"实体 + 一条链表", 影子档只搬实体 (M4)**:
  挂载那一步 `0x4A0540(城记录, 本人, 1)` 把本人**头插**进该城的家臣链表, 链表指针是**裸地址**
  (`[人+4]` = next, 表头在城记录 `+0`, 城记录 = `0x51eb88 + 城*31`)。原生存档把 +4..+7 存成**槽号**,
  载入时用 `idx*47 + 池基` 重算 (`0x47DD64`), 且 `idx>=370` 直接判 0 ⇒ 原生那一路必然把扩展槽的
  指针清掉; 我们的影子档在链尾 (`SITE_LOAD=0x47FBEE`, 真读遍**之后**) 整体回填 47B, 池基固定,
  所以 **RESTORE 成功的档里链表是完整的** (+4 是保存当时的裸地址, 前驱节点由原生按槽号重算成同一地址)。
  ⇒ 唯一残留边界: `SIDECAR_MISS / SIDECAR_REJECT` (老存档、换机、半截写) 时 `sc_reset` 把扩展槽贴回
  0x808F 空槽模板并清**儿童位图 + KID_TAB + CMD_RING**, 下一趟过钩走「位图未记账 + 空槽」重新
  `make_child` ⇒ 已元服的孩子**退回儿童态**, 到龄者当月**再元服一次** ⇒ `CHILD_GENPUKU` 比存档时 +1、
  五维与培养记录重来。这是"影子档没落地就重新生成"的取舍, 不是 bug;
  识别口径: `SIDECAR_MISS/REJECT` 涨了 **且** 同月 `CHILD_PRELOAD` 再涨一轮。
  反过来, RESTORE 正常时**不会**重复元服 —— 预载桩 `ours:` 分支的 `cmp al,0xf / je after`
  (位图已记账 + 在岗 + nibble 已 0xf ⇒ 一个字节都不碰) 就是专门为此加的。
