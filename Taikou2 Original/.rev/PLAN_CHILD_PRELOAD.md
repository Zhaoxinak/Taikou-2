## 2. 设计：三个部件，全部复用引擎自己的例程

目标不是"MOD 自绘一个假人"，而是让引擎数据结构里真的躺着一个活人（`生成的人物要实实在在能在游戏里有的`）。

**(1) 预载器 preloader —— 挂在已有月钩里，幂等**
```
遍历 scope 内 oid:
  登场标志[oid]==0 且 生年 <= 当前年 且 池内无该 oid
  → call 0x47f7b0(oid, 空槽)      # 引擎自带实体解码器: 47B 全字段 + 姓/名表写入
  → 登场标志[oid] = 1             # 原生通道从此永不再碰这个人(无双份/无二次登场)
  → 年龄 < 15 ? 打儿童标记 : 什么都不做(成年人交给原生初始化)
```
挂点选 `0x4A4CC0 → ensure_queue`（4i 已建）之后串一段，**不新增 hook**：新开局 / 读档 / 切剧本 / 跨年都会自然经过，天然幂等。

**(2) 儿童标记表 —— MOD 私有位图，零语义污染**
`.edata` 内 `N/8` 字节位图（512 槽=64B，768 槽=96B），按 **slot** 索引。
**不改** `word[+0x2c]` / `byte[+0x2d]` 任何一位 ⇒ 引擎看到的儿童就是一个普通在野实体，行为可预测；「谁是儿童」只有 MOD 知道。

**(3) 月度成长 / 元服调度 —— 同一个月钩**
```
age = 当前年 − (1490 + byte[ent+0x1b])
if 儿童标记[slot] and age >= 元服年龄:
    清标记; call 0x4a4fc0(ent)      # 引擎自带元服初始化(主君/所属/城 回退链)
else if 儿童标记[slot]:
    按培养曲线改 五维(+0x0a..0x0e)/技能(+0x0f..0x11)/忠诚(+0x29)/体力(+0x20,+0x21)
```
⇒ 儿童在场 → 每年长一波 → 15 岁**用引擎自己的元服例程**转成人 → 之后完全原生运作。这条线同时就是将来「生孩子系统」的成年线（新生儿 = 预载器造一个 0 岁儿童），复用度最高。

**「原剧本登场相关先别动」的落实**：不改 SNDATA/BSDATA 的登场数据、不改 `0x4A4D10` 算法语义、不改存档格式；预载器只在 MOD 侧加代码和位图。原生通道继续管它的 66 未出生 + 成年人排期。

## 5. 持久化（两条路，M6 前必须先选）

**方案 A · sidecar 影子存档（✅ 已选定，原格式零改动）**
- MOD 自己写 `CHILDSAVE.TR2`：每槽 `{slot, oid, 47B 实体记录, 儿童标记, 已培养字段}`
- 存档钩子：遍历扩展槽 370+ 落盘；读档钩子：回灌 + 重跑预载器补漏
- 优点：不动 6 个 `0x172` 文件锚，旧存档继续可用；容量抬到 768 也只是文件大 40KB
- 代价：MOD 挂了 = 儿童丢（但原存档主体无损）

**方案 B · P4 存档格式扩容**
- 序列化器 4 处 mov + 2 处 cmp 的 `0x172→0x200/0x2C0`，SNDATA/SAVEDATA 尾部补记录
- 优点：儿童进原生存档，无 sidecar 一致性问题
- 代价：**旧存档全部失效**、文件流后续段偏移被烧死（memory 记过：流内偏移 27052 依赖 370 条数）、风险面大得多

**先决**：M2/M3 阶段把儿童放进 **354..369 之外的扩展槽**可以跑通功能，但**跨读档不保真**；所以 M3 冒烟就要明确告知"这版读档会重放，培养结果可能回退"，或提前做方案 A 的最小版（只存 slot+oid+儿童标记+五维）。

## 10. 「无限扩容」架构（分五层；每层各自有天花板和解法）

> 关键认知：**槽位（在场人数）不是唯一天花板，甚至不是最先撞的那个。** 只抬 `CAP` 会在 662 人
> 处撞上 BSDATA 的 700 条档案墙、在各名单处撞上 16/288 的 per-list 上限。所以"无限"必须是
> **分层解耦**的，每层能独立生长、独立换档。

### L1 槽层（同时在场的人数）—— 已参数化，代价线性
每槽实打实 61B（47 实体 + 7 姓 + 7 名），`.edata` 大小由 `CAP` 推导：

| CAP | .edata | exe 增量 | 可用空槽 |
| --- | --- | --- | --- |
| 512 | 0x08000 | 基线 | 142 |
| **1024** | 0x10000 | +32KB（**已建**） | **654**（280 预载后余 374） |
| 2048 | 0x22000 | +160KB | 1678 |
| 4096 | 0x42000 | +384KB | 3726 |

- 上限来源不是内存：槽号全程走 word（原版 370>255 已证无 byte 宽假设）⇒ 理论 65535；
  实际约束是每月全池扫描 O(CAP) 的时间，以及 `0x172` 界检复核的完备性（504 站点由循环机械重写，点数断言恒等）。
- 🔴 **不可用「VirtualSize > RawSize 省磁盘」**：池尾若是全 0，状态字 `0x0000` = bit15 清 + bit7 清
  ⇒ 引擎判 `is_alive=1` ⇒ **凭空多出几千个"活着的空人"灌进每个名单**。静态 0x808F（bit7 置=不在场）
  必须逐槽真写，磁盘字节不能省。

### L2 档案层（oid 宇宙 = 可区分的人数）—— 当前墙 700，最先撞
预载者每人必须有一条 BSDATA 档案（oid 0..699）。280 预载后余 346 空 oid，**但新生儿/自定义人物会迅速吃光**。
解法（memory 里的 M2/M3，改动点已清点 <20 处）：
- **VBSD 镜像**：原 700×59B 整块拷进 `.edata`，尾部追加新档案；BSDATA 基址 `0x524a20` 全镜像
  **仅 7 处引用**（3 处序列化器写 + 4 处运行时读）⇒ 重定基只改那 4 个读点。
- 登场标志表 `0x519288`(700B) 与第二状态表搬家扩长；唯一运行时界检 `cmp si,0x2bc @0x4A4DFC` 抬到 N。
- 文件里的 `0x2bc`/`0xa154` 是**文件锚**，保留不动 ⇒ BSDATA*.TR2 与旧存档继续可用。
- ⇒ oid 上限变成与 `CAP` 同源的参数，与 L1 一起换档。**这才是"无限加人"的真闸门。**

### L3 持久层（sidecar，天然无上限）
- `TKMODSAVE.DAT`：`header{magic,ver,cap,n}` + 每条 `{slot, oid, 47B 实体, 儿童标记, 培养进度}`
- 只序列化 370+；0..369 继续由引擎自管，**双轨互不覆盖**。
- 存钩 `0x47DCE0` 尾 / 读钩 `0x47DF00` 尾；预载器幂等 ⇒ sidecar 丢了也只是"回到开局态"，不坏原存档。
- 4096 条 ×56B ≈ 230KB，容量再大也只是文件变大。

### L4 表现层（头像 / 名表 / 串池）
- 名表已搬家、按 slot 索引，随 `CAP` 自动长（L1 覆盖）。
- **头像 LS11 按 `bushou_id ≤ 699`** ⇒ L2 追加的新 oid 没脸 ⇒ 复脸（同族脸）或 modkit 等长扩容器（LS11 已破）。
- 只影响"700 墙外新增的人"；本次 280 预载全是真 oid，不受影响。

### L5 玩法层（per-list 上限——最容易被忽略的真瓶颈）
在场人数上去后，这些**固定容量数组**才是先炸的地方，放量前必须逐个审：

| 对象 | 现值 | 风险 |
| --- | --- | --- |
| 候选数组 `0x51e9c0` | 288 项 | 名单构建溢出/截断 |
| 各武将名单上限 | 16 项（`0x443810` 等） | 家臣/评定/劝诱列表显示不全（玩法失真，非崩） |
| 登场空缺槽表 | `(0x964-0x690)/2 = 362` | 280 人一次灌入仍在界内 ✓ |
| 登场候选(oid)表 | `0x690-0xc8 = 370` | 同上 ✓ |
| 城 200 / 国 49 | 固定 | 280 人走浪人态不需要 280 座城，但要审安置回退链 |

⇒ **无限扩容的正确姿势**：`CAP` 与 `N_OID` 同步抬（L1+L2）→ sidecar 跟着变长（L3）→ 头像按 oid 补（L4）
→ 而 **L5 不是参数，是逐个函数的行为**，必须按批冒烟审。

## 8. 埋点（沿用你既有口径，`tkwatch.py` 增行）

MOD 私有区当前已吃到 +0xB0（`EQ_STUB` 尾），新计数器直接从 **+0xC0** 起排（`build_big.py` 里加
`M(0xC0)…` 即可，`_big_layout.json` 自动带出，`tkwatch.py` 自动跟随，无需手改地址）：
`PRELOAD_SCAN`（预载器执行次数≈月）/ `PRELOAD_HIT`（成功实例化人次）/ `CHILD_ALIVE`（当前儿童数，调度器每月覆写）/ `GENPUKU_CNT`（元服触发次数）/ `SIDECAR_SAVE/LOAD`（影子存档读写次数）。
判读：`PRELOAD_SCAN>0` 而 `PRELOAD_HIT=0` ⇒ scope 判据或空槽不足；`CHILD_ALIVE` 掉到 0 ⇒ 读档把扩展槽冲掉了。
