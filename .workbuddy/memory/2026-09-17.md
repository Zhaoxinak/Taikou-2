# 2026-09-17 工作日志

## git 状态修复：`main [origin/main: ahead 24]` 是**假象**（跟踪引用丢失）

**症状**：`git branch -vv` 显示 `[origin/main: ahead 24]`，24 个提交（83396bc..f71693f 大地图 3D/坐标/路网系列）看着像未推送；`git log origin/main..HEAD` 也列出 24 条。但 `git push` 回 **Everything up-to-date**。

**判定**：`git ls-remote origin main` → `f71693f`，**与本地 HEAD 逐字符相同** ⇒ 远端早就有了，纯属本地 `origin/main` 跟踪引用丢失导致 ahead 计数失真。

**根因**：`.git/refs/remotes/origin/` 目录**不存在**（`git fetch` 打印 `* [new branch] main -> origin/main` 却**没落盘**；`git update-ref refs/remotes/origin/main <sha>` 返回 0 也不落盘）。`.git/sourcetreeconfig.json` 存在 + 工作区有 `_hd6_run.log`/`tmp_*.png` 等另一会话痕迹 → 疑并发进程（SourceTree/其它会话）干扰引用写入。

**修法（实测有效）**：绕开 git 直接落盘引用文件
```bash
mkdir -p .git/refs/remotes/origin
printf 'f71693fd541004dfc3e1f31f48d69b348e1152d1\n' > .git/refs/remotes/origin/main
```
`git rev-parse --verify origin/main` 通过；`git branch -vv` 变 `[origin/main]`（无 ahead/behind）；`git rev-list --left-right --count origin/main...HEAD` = `0 0`；复查 2s 后引用仍在（持久）。

**教训**：`ahead N` ≠ 未推送。**先 `git ls-remote origin main` 比对 sha**，相同就说明只是跟踪引用坏了，别重复 push、更别在"以为 ahead"时做 rebase/reset。
